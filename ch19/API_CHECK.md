# 공공데이터포털 API 확인 결과

최초 확인일: 2026-07-01 KST
업종 매핑 재확인일: 2026-07-19 KST

키 값은 출력하지 않았다. 각 API는 공공데이터포털 금융위원회 OpenAPI로 확인했다.

## 인증키 보관 방식

앱은 공공데이터포털 인증키를 코드에 직접 넣지 않는다. 서버 실행 시 `DATA_GO_KR_SERVICE_KEY` 환경변수를 읽어 실제 API 데이터를 가져온다. 프로젝트별 `.env` 파일을 쓰거나, 반복 설정을 줄이고 싶다면 쉘/OS 환경변수로 한 번만 설정한다.

## 업종 지수 매핑 재확인

2026-07-19에 [금융위원회 지수시세정보](https://www.data.go.kr/data/15094807/openapi.do)의 최신 거래일 전체 168행을 조회하고 `idxCsf`와 `idxNm`을 정확히 대조했다. 현재 `SECTOR_INDEX_MAP`의 11개 지수는 모두 `basDt=20260715` 응답에 존재했다.

| 화면 업종 | `idxCsf` | `idxNm` |
| --- | --- | --- |
| 반도체 | `KRX시리즈` | `KRX 반도체` |
| 자동차 | `KRX시리즈` | `KRX 자동차` |
| 2차전지 | `테마지수` | `KRX 2차전지 TOP 10 지수` |
| 조선 | `테마지수` | `KRX 조선 TOP10 지수` |
| 금융 | `KRX시리즈` | `KRX 300 금융` |
| 헬스케어 | `KRX시리즈` | `KRX 헬스케어` |
| 유통 | `KOSPI시리즈` | `유통` |
| 게임 | `테마지수` | `KRX 게임 TOP 10 지수` |
| 방송통신 | `KRX시리즈` | `KRX 방송통신` |
| 오락·문화 | `KOSPI시리즈` | `오락·문화` |
| 건설 | `KRX시리즈` | `KRX 건설` |

- 조선·게임·2차전지는 공식 응답에서 `테마지수`로 분류된 각 `TOP 10` 지수를 채택했다. 화면에서도 출처를 `테마지수`로 표시하며, 전체 상장사를 포괄하는 산업분류 지수로 표현하지 않는다.
- 같은 응답 전체에서 `화장품`, `뷰티`, `코스메틱`을 포함하는 지수명은 확인되지 않았다. 화장품 타일은 계속 제외하며 다른 소비재 지수나 임의 계산값으로 대신하지 않는다.
- 2차전지는 함께 제공되는 `KRX K-AI 2차전지 지수`가 아니라 범용적인 `KRX 2차전지 TOP 10 지수`를 정확히 매핑한다.

## 화면 영역별 요구 데이터와 처리

| 화면 영역 | 화면 칸 | 필요한 데이터 | 공식 API로 채움 | 처리 방식 |
| --- | --- | --- | --- | --- |
| 지수 카드 | KOSPI/KOSDAQ 지수값, 등락폭, 등락률, 거래대금 | 지수명, 종가 포인트, 전일대비, 등락률, 거래대금 | 가능 | 지수시세정보에서 `idxCsf`/`idxNm`으로 `코스피`, `코스닥`을 찾는다. |
| 지수 카드 | 상승/하락/보합 종목 수, 종목 상승 비율 | 시장구분, 종목별 등락률 | 가능 | 주식시세정보의 `mrktCtg`, `fltRt`를 KOSPI/KOSDAQ별로 집계한다. |
| 시장 열기 | 3% 이상 상승 종목 비율, 상승/하락 종목 수, 전체 거래대금 | 종목별 등락률, 거래대금 | 가능 | 공공데이터포털에 별도 "시장 열기" 지표는 없으므로 `fltRt >= 3` 비율로 계산한 지표를 명시해 표시한다. |
| 업종 히트맵 | 업종명, 등락률, 거래대금 | 공식 지수명, 지수 등락률, 거래대금 | 가능(매핑된 공식 지수만) | 지수시세정보의 `idxCsf`와 `idxNm`이 `SECTOR_INDEX_MAP`과 모두 일치하는 지수만 표시한다. 매핑 지수가 없으면 해당 칸은 렌더링하지 않는다. |
| 종목 순위 | 상승률 상위, 하락률 상위, 거래대금 상위 | 종목명, 시장구분, 종가, 등락률, 거래대금 | 가능 | 주식시세정보를 `fltRt`, `trPrc` 기준으로 정렬해 상위 5개를 만든다. |
| 관심 종목 | 검색 후보, 관심 종목 카드 | 종목 코드, 종목명, 시장구분, 종가, 등락률 | 가능 | 주식시세정보 또는 Supabase 일별 시세에서 검색 후보를 만들고, 선택한 코드는 `/api/watchlist`를 통해 Supabase `watchlist_stocks`에 저장한다. |
| 종목 검증 | 화면에 직접 표시하지 않음 | 상장 단축코드 | 가능 | 상장종목정보의 `srtnCd`로 주식시세 종목 코드를 검증한다. |

## 화면에서 빼거나 분리한 항목

| 항목 | 공식 API 처리 가능 여부 | 결정 |
| --- | --- | --- |
| 공공데이터포털이 제공하는 별도 "시장 열기" 원천 지표 | 불가 | 임의 지표처럼 보이지 않도록 `3% 이상 상승 종목 비율` 계산값으로 확정했다. |
| 화장품 업종 지수 | 현재 응답에서 확인 불가 | 이름이 비슷한 소비재 지수나 예시값으로 대신하지 않고 히트맵에서 제외한다. |
| 실시간 개장 여부, 장중 가격, 초 단위 갱신 | 불가 | 현재 화면에 넣지 않는다. 세 API는 일별 기준 데이터다. |
| 로그인 계정별 관심 종목 저장/동기화 | 범위 밖 | 현재는 로그인과 `user_id` 없이 하나의 Supabase `watchlist_stocks` 목록을 공유한다. 사용자별 목록처럼 표현하지 않는다. |
| 외국인/기관 수급, 투자 추천 | 불가 또는 범위 밖 | 현재 화면에 넣지 않는다. |

## 실패와 갱신 지연 처리

- 종목 시세는 먼저 Supabase `daily_stock_prices`의 최신 적재일을 사용하고, 연결 또는 조회가 실패하면 공공데이터포털 주식시세정보를 직접 조회한다.
- 지수시세정보와 종목 시세는 최신 기준일이 다를 수 있다. 앱은 지수 기준일과 종목 기준일을 따로 찾고 헤더에 함께 표시한다.
- Supabase와 공공 API 경로가 모두 실패하거나, 비정상 `resultCode`, 빈 응답, 필수 지수 누락, 종목 데이터 부족이 발생하면 `exampleMarketData`로 fallback한다.
- fallback 데이터는 `dataNotice`에 실패 이유를 붙여 실제 데이터처럼 보이지 않게 표시한다.
