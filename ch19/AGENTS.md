# AGENTS.md

## 작업 시작 전

- 먼저 `README.md`의 **결정 기록**, **데이터 출처와 기준일**, **계산 기준**, **알려진 한계**를
  끝까지 읽는다. 기존 결정을 바꾸려면 공식 근거와 사용자 승인을 먼저 확보한다.
- `git status --short`를 확인하고 기존 사용자 변경을 보존한다. 관련 없는 변경을 되돌리거나
  한 커밋에 섞지 않는다.
- `.env.sample`에서는 환경변수 이름만 확인한다. 다른 `.env` 파일의 값은 읽거나 출력하거나
  커밋하지 않는다.

## 코드 변경과 검증

- **코드를 바꾸면 검증부터** 한다. 관련 단위 테스트를 먼저 실행하고, 완료·커밋·공유 전에
  반드시 `npm test`를 실행해 Node 테스트와 Next.js 프로덕션 빌드 결과를 보고한다.
- 표시·계산·데이터 변환 로직을 바꿀 때는 정상값뿐 아니라 예시 데이터, 빈 값, 오류 폴백,
  기준일 차이도 테스트한다.
- 프로덕션 배포를 공유하거나 릴리스를 최종 확인할 때는 테스트 통과 뒤
  `verify-market-dashboard` Skill을 사용한다. Skill의 앱별 완료 기준을 읽고, 최신
  프로덕션 배포와 대상 Git SHA, 실제 화면과 기준일·시세, 최근 5xx, 환경변수 **이름** 계약,
  Git 비밀 검사를 읽기 전용으로 확인한다.
- Vercel MCP가 없거나 프로젝트를 하나로 식별하지 못하면 추측하거나 설치·로그인을 자동으로
  시도하지 말고 Skill 규칙대로 `WARNING`을 보고한다. `예시 데이터`가 프로덕션에 보이면
  통과로 판정하지 않는다.
- 문서만 바꾼 경우에도 `git diff --check`, 링크·경로, `.env.sample`과 코드의 환경변수 이름
  일치를 확인한다.

## 화면 모드 규칙

- 저장된 선택이 없으면 `prefers-color-scheme`으로 컴퓨터 화면 설정을 따른다.
- 사용자가 시스템·라이트·다크 중 고른 값을 `localStorage`에 기억하고 다음 방문에서 컴퓨터
  기본값보다 우선한다. 사용자가 시스템 모드를 고른 동안에는 운영체제 설정 변경을 따라간다.
- 두 테마 모두에서 모든 카드·입력·표의 대비를 유지한다. 상승과 하락은 색만으로 구분하지
  않고 각각 `+`와 `−` 부호를 함께 표시한다.

## 병렬 작업 규칙

- 병렬 작업이 필요하면 작업자마다 별도 Git worktree와 브랜치를 만들고 담당 파일을 겹치지
  않게 나눈다. 여러 에이전트가 같은 체크아웃의 같은 파일을 동시에 수정하지 않는다.
- 각 작업자는 자기 worktree에서 관련 테스트와 변경 범위를 보고한다. 결과 통합, 충돌 해결,
  전체 `npm test`, 최종 커밋은 메인 Codex가 담당한다.
- 통합 전 각 브랜치의 커밋과 diff를 검토하고, 관련 없는 파일이나 생성물을 가져오지 않는다.

## 하지 말 것

- 공식 응답에서 정확한 업종 매핑을 검증하지 못한 항목을 유사 지수, TOP 10 테마지수, 임의
  종목 묶음이나 산식으로 채우지 않는다. 산업분류 지수처럼 보이면 사용자가 공식 업종 흐름으로
  오해하기 때문이다. 특히 조선·게임·2차전지 TOP 10은 테마지수로만 취급하고, 화장품은 대응
  지수를 확인할 때까지 비워 둔다.
- 인증키, 토큰, 프로젝트 비밀값을 코드·문서·테스트 fixture·커밋 메시지에 적지 않는다.
  `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`도 반드시 환경변수로만 전달한다.
- `예시 데이터` 출처 안내나 기준일을 숨기지 않는다. 수집 실패를 실제 시세처럼 보이게 만들면
  안 된다.
- 로그인·결제·주문·실제 증권 계좌 연동은 이 프로젝트 범위 밖이다. 계좌 연결 없이 보유
  수량·평가금액·수익률을 임의 숫자로 만들지 않는다. 범위를 넓히려면 별도 보안·개인정보·
  금융 데이터 설계와 사용자 승인이 먼저 필요하다.
