# Supabase 시세를 읽는 국내 주식 대시보드

Supabase `daily_quotes`의 최신 종가와 금융위원회 공공데이터포털의 시장 지표를 한
화면에 보여 주는 학습용 Next.js 대시보드다. 실시간 투자 서비스가 아니며, 외부
수집이 실패하면 화면을 비우지 않고 명확한 `예시 데이터` 안내와 함께 견본 수치를
표시한다.

## 처음 시작하는 3단계

### 1. 설치

Node.js 20 이상에서 저장소 루트로 이동해 잠금 파일 기준으로 의존성을 설치한다.

```bash
npm ci
```

### 2. 환경변수

프로젝트 루트의 .env.sample을 .env로 복사하고 실제 값을 입력한다. 로컬
환경파일은 Git에 커밋하지 않는다. .env.sample의 키 계약은 다음 세 줄이며 값은
항상 비워 둔다.

```dotenv
DATA_GO_KR_SERVICE_KEY=
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
```

| 이름 | 용도 | 주의 |
| --- | --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | 금융위원회 공공데이터포털 API 인증 | 서버 코드에서만 읽고 브라우저나 소스에 노출하지 않는다. |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 URL | 앱의 읽기 요청에 사용한다. |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase publishable key | 브라우저에 공개되는 클라이언트 키다. 앱은 이 키로 시세를 읽기만 하고, 쓰기 경로는 앱에 두지 않는다. |

Vercel의 Production·Preview·Development 환경에도 이름이 같은 세 변수를 설정한다.
값은 로컬 문서, Git diff, 로그, AI 대화에 복사하지 않는다.

### 3. 실행

```bash
npm run dev
```

기본 주소는 `http://localhost:3000`이다. 전체 자동 검사는 `npm test`로 실행한다.
이 명령은 Node 테스트와 Next.js 프로덕션 빌드를 차례로 수행한다.

## Supabase MCP와 Vercel 재연결

연결 정보는 저장소에 커밋되지 않는다. 새 컴퓨터나 새 Codex 세션에서는 아래 절차로
다시 연결한다.

### Supabase MCP

Supabase 프로젝트의 Reference ID를 확인한 뒤 프로젝트 범위와 읽기 전용 옵션을
함께 사용한다. 기존 연결이 잘못됐을 때만 첫 줄을 실행한다.

```bash
codex mcp remove supabase
codex mcp add supabase --url 'https://mcp.supabase.com/mcp?project_ref=<PROJECT_REF>&read_only=true'
codex mcp login supabase
```

앱은 `daily_quotes`를 GET으로만 읽는다. 필요한 열은 `trade_date`, `stock_code`,
`stock_name`, `close_price`, `change_rate`, `trading_value`다. 공개된 시세만 담는 학습용
프로젝트라 RLS는 켜지 않았고, 시세 적재는 앱이 아니라 이 학습용 Supabase MCP로만 한다.
그래서 MCP 주소에 `&read_only=true`를 붙여 잠가 두고, 적재할 때만 잠시 푼다. 자세한 연결
옵션은 [Supabase MCP 공식 문서](https://supabase.com/docs/guides/ai-tools/mcp)를 따른다.

### Vercel 프로젝트와 MCP

로컬 폴더를 기존 Vercel 프로젝트에 다시 연결한다. `vercel link`가 만드는 `.vercel/`
폴더는 Git에 커밋하지 않는다.

```bash
npx vercel login
npx vercel link
```

Codex에서 배포 상태를 읽으려면 공식 Vercel MCP도 연결한다. 기존 연결이 잘못됐을
때만 첫 줄을 실행하며, `add` 과정에서 브라우저 OAuth 승인을 마친다.

```bash
codex mcp remove vercel
codex mcp add vercel --url https://mcp.vercel.com
```

프로젝트 연결은 [Vercel CLI project linking](https://vercel.com/docs/cli/project-linking),
MCP 연결은 [Vercel MCP 공식 문서](https://vercel.com/docs/agent-resources/vercel-mcp)를
기준으로 한다.

## 데이터 출처와 기준일

| 화면 | 데이터 출처 | 기준 |
| --- | --- | --- |
| 관심 종목·종목 비교·종목 순위 | Supabase `daily_quotes` | 가장 최신 `trade_date`의 종가·등락률·거래대금 |
| KOSPI·KOSDAQ 카드 | 금융위원회 공공데이터포털 지수시세정보 | 최신 `basDt` 종가·전일 대비·등락률과 최근 거래일 종가 흐름 |
| 시장 열기 | 금융위원회 공공데이터포털 주식시세정보 | 최신 `basDt`의 KOSPI·KOSDAQ 종목 |
| 산업분류 히트맵 | 금융위원회 공공데이터포털 지수시세정보 | 같은 기준일의 정확한 `KRX시리즈` 산업분류 지수 |
| 테마 지수 | 금융위원회 공공데이터포털 지수시세정보 | 같은 기준일의 정확한 `테마지수` TOP 10 지수 |
| 폴백 화면 | `data/marketSnapshot.js` | 외부 조회 실패를 설명하기 위한 명시적 예시 값 |

공공데이터는 실시간이 아니며 기준 거래일의 **다음 영업일 오후 1시 이후** 갱신될 수
있다. 주말·공휴일·임시 휴장일에는 새 기준일이 생기지 않으므로 화면에는 오늘 날짜가
아니라 마지막으로 공개된 거래일이 표시되는 것이 정상이다. 주식시세와 지수시세의
최신 기준일이 다르면 섞지 않고 조회 실패로 처리한다. 앱은 1시간 단위로 데이터를
재검증하며, 공개 데이터가 한국 날짜 기준 7일보다 오래되면 예시 데이터로 전환한다.

Supabase는 종목 시세만 담당한다. 지수 카드·시장 열기·산업분류 히트맵·테마 지수는
Supabase에 없는 값을 만들지 않고 계속 공공데이터 경로에서 읽는다. Supabase가 실패하면
종목 시세도 공공데이터로 대체하고, 두 외부 소스가 모두 실패할 때만 전체 예시 스냅샷을
사용한다.

## 계산 기준

시장 열기는 등락률을 읽을 수 있는 KOSPI·KOSDAQ 종목 중 **3% 이상 상승한 종목 수의
비율**이다.

```text
시장 열기(%) = 3% 이상 상승 종목 수 / 유효한 등락률이 있는 전체 종목 수 × 100
```

이 비율을 그대로 0~100%로 표시한다. 종목별 가중치, 시가총액 보정, 곡선 변환,
감성지수 같은 별도 가공 점수는 만들지 않는다. 분모가 없거나 입력이 잘못된 경우에만
안전하게 0으로 처리하고, 비율이 범위를 벗어나면 0~100 사이로 제한한다.

종목 순위는 최신 기준일 데이터에서 상승률·하락률·거래대금을 정렬한 상위 5개다.
거래대금은 원 단위 원본을 억원 또는 조원으로 바꾸어 표시할 뿐 순위 산식은 바꾸지
않는다.

## 결정 기록

다음 결정은 데이터의 의미를 과장하거나 가짜 정밀도를 만들지 않기 위해 유지한다.

### 업종과 테마를 구분한다

최신 공식 응답에서 확인한 이름과 분류는 다음과 같다.

| 화면 후보 | 공식 지수명 | 공식 분류 | 현재 처리 |
| --- | --- | --- | --- |
| 조선 | `KRX 조선 TOP10 지수` | `테마지수` | 별도 테마 지수 영역에 표시 |
| 게임 | `KRX 게임 TOP 10 지수` | `테마지수` | 별도 테마 지수 영역에 표시 |
| 2차전지 | `KRX 2차전지 TOP 10 지수` | `테마지수` | 별도 테마 지수 영역에 표시 |
| 화장품 | 확인하지 못함 | 확인하지 못함 | 숨김 |

조선·게임·2차전지는 위 공식 지수명과 `테마지수` 분류를 정확히 함께 매핑해 별도 테마
지수 영역에 표시한다. 이 지수들을 일반 산업 전체의 등락률인 것처럼 표현하지 않는다.
산업분류 히트맵에는 같은 이름의 `KRX시리즈` 산업분류 지수를 확인한 `반도체·자동차·
은행·증권·건설·철강·운송·방송통신` 8개만 표시한다.

화장품은 최신 응답에서 정확한 대응 지수를 확인하지 못했다. 비슷해 보이는 소비재
지수를 대신 붙이거나 일부 종목을 임의로 평균 내면 지수의 구성과 가중치가 달라지므로
그렇게 채우지 않는다.

### 지수 카드의 미니 차트는 장중이 아니라 최근 종가다

공개 API는 하루치 종가만 주고 시간대별 값을 주지 않는다. 그래서 지수 카드의 선은
장중 흐름이 아니라 같은 응답에서 모은 최근 거래일 종가를 잇는다. 없는 시간대 값을
만들어 채우지 않으며, 필드 이름도 `recentCloses`로 두어 의미가 흐려지지 않게 한다.
응답에 거래일이 하나뿐이면 이 칸만 비운다. 미니 차트 하나 때문에 화면 전체를 예시
데이터로 떨어뜨리지 않는다.

### 보유 종목과 수익률은 만들지 않는다

이 프로젝트에는 로그인과 실제 계좌 연동이 없다. 따라서 보유 수량·평균 매수가·평가
손익·수익률을 표시하면 모두 가짜 숫자가 된다. 관심 종목은 브라우저 `localStorage`에
종목코드만 저장하며 실제 보유 자산이라고 표현하지 않는다.

### 종목 비교는 두 종목까지만 둔다

비교 화면의 목적은 서로 다른 두 종목의 현재가와 오늘 등락률을 한 화면에서 나란히
읽는 것이다. 비교 대상을 늘리면 표와 필터가 필요해져 이 단순한 목적이 흐려지므로 두
종목으로 제한한다. 선택은 현재 브라우저에만 저장한다.

### `예시 데이터` 안내를 지우지 않는다

`예시 데이터` 배지는 장식이나 개발용 문구가 아니라 Supabase 또는 공공데이터 수집
실패를 사용자에게 알리는 데이터 출처 표시다. 예시 값을 실제 시세로 오해하지 않도록
배지·상단 안내·하단 고지를 함께 유지한다. 실패 상황을 숨기기 위해 문구만 삭제하거나
실데이터 배지로 바꾸지 않는다.

### 화면 모드 선택을 기억한다

저장된 선택이 없으면 컴퓨터의 `prefers-color-scheme` 설정을 따른다. 사용자가 라이트
또는 다크 모드를 고르면 `localStorage`에 저장하고 이후에는 컴퓨터 설정보다 우선한다.

## 알려진 한계

- 실시간·장중 데이터, 주문, 투자 자문을 제공하지 않는다.
- Supabase 데이터의 적재 작업은 앱 바깥에서 이루어진다. 앱에는 쓰기 경로가 없다.
- 7일 초과 장기 휴장이나 외부 데이터의 갱신 지연은 오래된 데이터로 판정되어 예시
  화면을 만들 수 있다.
- 조선·게임·2차전지는 산업분류가 아닌 별도 테마 지수로 표시한다. 화장품은 정확한
  대응 지수를 확인하지 못해 표시하지 않는다.
- 관심 종목·비교 선택·화면 모드는 브라우저별 `localStorage`에만 남고 기기 사이에서
  동기화되지 않는다.
- 계정, 로그인, 결제, 실제 증권 계좌, 보유 종목과 개인 수익률은 지원하지 않는다.
- 화면은 폭 1200px 이상의 데스크톱 사용을 우선해 설계됐다.

## 복구와 배포 롤백

### 로컬 변경 복구

먼저 변경 범위를 확인한다.

```bash
git status --short
git diff
```

커밋하지 않은 변경을 버리기 전에는 필요한 diff를 별도 파일이나 커밋으로 보관한다.
정확한 파일만 원래 상태로 되돌리고 저장소 전체를 무차별 초기화하지 않는다.

```bash
git restore --source=HEAD -- <파일>
```

이미 공유한 커밋은 이력을 지우는 reset 대신 새 되돌림 커밋을 만든다.

```bash
git revert <문제-커밋-SHA>
npm test
```

외부 조회 실패는 먼저 세 환경변수 **이름**, Supabase `daily_quotes`의 테이블 이름과 최신
행, 공공데이터 기준일을 확인한다. 키 값은 출력하지 않는다. 원인을 고치는
동안에도 `예시 데이터` 안내를 삭제하지 않는다.

### Vercel 프로덕션 롤백

배포한 뒤에는 `$verify-market-dashboard` Skill로 최신 Production 배포의
Ready 상태, Git SHA, 실제 화면, 최근 반복 5xx, 환경변수 이름 계약과 비밀 노출을 읽기
전용으로 검사한다.

문제가 있는 프로덕션을 이미 배포했다면 Vercel 대시보드의 Instant Rollback 또는
연결된 프로젝트에서 다음 명령을 사용한다.

```bash
npx vercel rollback
# Pro·Enterprise에서 특정 과거 배포를 고를 때:
npx vercel rollback <정상-배포-URL>
npx vercel rollback status
```

Hobby 요금제는 바로 이전 프로덕션으로만 롤백할 수 있다. 롤백은 기존 빌드로 트래픽을
돌리는 동작이므로 외부 Supabase 데이터나 현재 환경변수까지 되돌리지 않는다. 정상화
후 새 배포를 다시 Production으로 올리려면 다음처럼 승격한다.

```bash
npx vercel promote <배포-URL>
```

절차와 요금제 차이는 [Vercel 프로덕션 롤백 공식 문서](https://vercel.com/docs/deployments/rollback-production-deployment)를
따른다.

## 남은 일

- 화장품의 공식 대응 지수가 생겼는지 공공데이터의 최신 응답과 KRX 문서에서 다시
  확인한다. 확인 전에는 대체 지수나 임의 산식을 넣지 않는다.
- Supabase 일별 적재의 성공 여부와 데이터 기준일 지연을 감시하고 실패 알림을 만든다.
- 7일 초과 연휴를 거래소 영업일 달력으로 판정할지 검토한다.
- 1200px 미만 화면을 위한 반응형 레이아웃과 접근성 검사를 보강한다.
- 배포 전 `npm test`와 `$verify-market-dashboard` 결과를 인수인계 기록에 남긴다.
