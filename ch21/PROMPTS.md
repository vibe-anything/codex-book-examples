# 21장 프롬프트 모음

아래 요청문은 15~20장에서 이어 온 주식 대시보드의 원래 작업 폴더에서 Codex 한 세션을 연 뒤,
장의 흐름에 맞춰 복사해 붙여넣습니다. 독자가 기능별 터미널이나 Codex 세션을 따로 열지 않고,
메인 Codex가 Git worktree 두 곳과 subagent 두 명을 준비해 병렬 작업을 관리합니다.

이 폴더(`ch21`)는 종목 비교와 다크 모드를 병합한 완성 스냅숏입니다. 실제 병렬 작업을 처음부터
재현하려면 20장까지 마친 별도의 깨끗한 Git 작업본에서 시작합니다. 완성 스냅숏에 1번 요청을
다시 보내면 같은 기능을 중복해서 만들 수 있습니다.

비밀 `.env`, 운영 데이터, 실제 계좌 정보는 Codex 대화나 worktree에 복사하지 않습니다. 예시
데이터만으로 두 기능을 만들고 검사합니다.

## 0. 원래 작업 폴더에서 Codex 열기

`path/to/my-market-dashboard`는 20장까지 작업한 자신의 대시보드 경로로 바꿉니다.

```bash
cd path/to/my-market-dashboard
codex
```

이미 다른 worktree 안에서 작업 중이라면 그곳에서 계속하지 않고 원래 작업 폴더로 돌아옵니다.
추적·미추적 변경이 남아 있다면 임의로 커밋하거나 숨기지 말고 먼저 내용을 확인합니다.

## 1. 두 기능을 worktree에서 병렬로 만들고 합치기

다음 요청 하나로 작업 상태 확인, worktree 생성, subagent 병렬 실행, 검사와 순차 병합까지
맡깁니다.

```text
대시보드에 두 기능을 동시에 만들어줘.

만들 것
- 종목 비교: 서로 다른 두 종목의 현재가와 오늘 등락률을 나란히 보여주고, 선택을 기억한다.
  같은 종목을 고르면 다른 종목을 고르도록 알려준다.
- 다크 모드: 처음에는 컴퓨터 화면 설정을 따르고, 내가 고른 화면 모드를 기억한다.
  모든 카드와 상승·하락 정보는 두 화면에서 또렷하게 보여주고, 색과 부호로 함께 구분한다.

진행
- 먼저 지금 작업을 잃을 위험이 없는지 확인해줘.
- 안전하면 기능마다 별도 git worktree와 subagent 한 명을 배정해 병렬로 구현해줘.
- 각 subagent에게 작업 경로·브랜치·수정 범위를 알려주고, 올바른 작업장인지 확인한 뒤 시작하게 해줘.
- 별도 작업장에 쓸 권한이 없으면 같은 폴더에서 진행하지 말고 멈춰서 알려줘.

완료
- 각 subagent가 맡은 범위만 예시 데이터로 검사해 커밋하게 해줘.
- 둘 다 통과하면 시작점 대비 각 변경을 검토하고 하나씩 합쳐줘. 충돌이나 제품 결정이 필요하면 현재 병합을 중단하고 알려줘.
- 홈과 비교 화면의 두 모드, 기존 기능, 자동 검사와 빌드까지 확인해줘.
- 두 subagent가 실제로 병렬 실행됐는지, 시작 커밋과 최종 결과 사이의 Diff 요약, 최종 주소를 보여줘.
- push·배포·작업장 정리는 하지 마.
```

Codex가 저장하지 않은 변경이나 권한 문제를 발견해 멈추면 그것이 정상입니다. 같은 폴더에서
작업하도록 강행하지 말고, 보고된 문제를 확인한 뒤 안전한 상태에서 다시 요청합니다.

## 2. 합친 제품 직접 확인하기

완료 보고가 오면 최종 주소를 열고 다음 세 묶음을 사람이 직접 확인합니다.

1. 서로 다른 종목 두 개를 고르고 바꿀 수 있는지, 같은 종목을 고르면 다음 행동을 알려 주는지
   봅니다.
2. 홈과 비교 화면을 밝게·어둡게 바꾸고, 새로고침 뒤에도 비교 종목과 화면 모드 선택이 남는지
   확인합니다.
3. 기존 관심 종목과 시장 화면이 그대로 동작하고, 자동 검사와 빌드가 통과했는지 확인합니다.

화면이나 동작이 기대와 다르면 작업장부터 정리하지 않습니다. 같은 메인 Codex 세션에 관찰한
문제를 말하고, 수정 뒤 세 묶음을 다시 확인합니다.

## 3. 최종 확인 뒤 작업장 정리하기

다음 요청은 합친 화면과 변경 사항을 사람이 모두 확인한 뒤에만 보냅니다. 첫 요청에서 작업장을
정리하지 말라고 했으므로, 결과 확인 전에는 이 후속 요청을 보내지 않습니다.

```text
최종 결과를 확인했어. 합친 커밋이 원래 프로젝트에 남아 있는지 다시 확인하고, 이번 작업에 만든 worktree와 작업용 브랜치만 안전하게 정리해줘.
```

정리가 끝나면 원래 프로젝트의 최종 커밋과 Git 상태를 다시 확인합니다. 이번 작업과 관계없는
worktree나 브랜치는 삭제하지 않습니다.
