# 5장 요청문 — Codex가 이해할 프로젝트 맥락 만들기

이 폴더는 5장을 **끝낸 직후** 상태다. `ch04/real-estate-app`을 복사한 뒤 아래 요청문을 책
순서대로 Codex에 입력해 만들었다.

API 키가 없어도 연습용 데이터로 목록이 보인다. 키 없음·거래 없음·호출 실패 상태는 서버 설정
(`MOCK_API_KEY_MISSING`, `MOCK_EMPTY`, `MOCK_API_FAILURE`)으로 켜서 본다. Next.js는 프로젝트
루트의 `.env`를 읽으므로 `MOCK_EMPTY=true` 같은 줄을 `.env`에 넣고 서버를 다시 시작해도 된다.

## 1. Next.js 골격부터 맞추기 (§5.1)

```text
이 프로젝트를 Next.js 프로젝트 구조로 마이그레이션해 줘.
```

마이그레이션이 끝나면 `npm run dev`로 첫 화면이 열리는지 확인한다. 첫 화면이 열렸다면
되돌아올 지점을 남긴다.

```text
이 프로젝트를 Git 저장소로 만들고, 지금까지 만든 파일을 첫 커밋으로 남겨 줘.
```

## 2. AGENTS.md 초안 요청하기 (§5.4)

아파트 실거래가 앱 프로젝트 폴더에서 Codex를 열고 요청한다.

```text
이 프로젝트를 살펴보고 프로젝트의 맨 위 폴더에 AGENTS.md 파일을 만들어 줘.
Codex가 이 프로젝트에서 매번 지켜야 할 규칙을 한국어로 정리해 줘.
- 어떤 앱이고 어떤 파일이 무슨 역할을 하는지 개요와 구조부터 적어 줘.
- 거래 금액은 만원 단위 숫자로 파싱하고, 화면에는 억/만 원 단위로 보여 줘.
- API 키는 코드에 직접 쓰지 말고 .env에서 읽어.
- 빈 응답, 인증 오류, 파라미터 오류를 구분해 줘.
- 변경한 후에 무엇으로 확인할지 검증 명령도 적어 줘.
```

Codex가 만드는 AGENTS.md는 제목과 순서가 실행마다 조금씩 다르다. 이 폴더의 `AGENTS.md`가
책에 실린 예시와 같은 모양이다. 모양이 달라도 담긴 규칙이 같으면 된다.

## 3. 규칙을 남긴 후 같은 요청 다시 하기 (§5.6)

```text
AGENTS.md 기준으로 실거래가 API 응답 파싱 규칙을 점검해 줘.
```

점검 요청을 받은 뒤에는 사람이 직접 본다.

- 변경 파일에서 API 키나 `.env` 값이 코드·로그에 드러나지 않았는지
- 빈 응답, 인증 오류, 파라미터 오류가 서로 다른 메시지와 상태로 처리되는지
- `npm test`와 필요한 경우 `npm run build`가 실제로 통과하는지
- 화면에서 거래 금액이 약속한 억/만 원 형식으로 보이는지

확인이 끝나면 AGENTS.md까지 커밋해 되돌아올 지점을 하나 더 남긴다. 7장의 첫 `/diff`는 마지막
커밋을 기준으로 바뀐 것을 보여 준다.

```text
AGENTS.md까지 포함해 지금까지 바뀐 파일을 커밋해 줘.
```
