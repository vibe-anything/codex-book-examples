# 17장 프롬프트 모음

아래 요청문은 `vibecoding-codex-book-examples/ch17` 폴더에서 `codex`를 실행한 뒤, 장의 흐름에 맞춰 하나씩 복사해 붙여넣습니다.

이 장은 16장에서 만든 국내 시장 대시보드에 작은 사용자 기능을 추가한 뒤, Codex 훅으로 검증 습관을 자동화하는 예제입니다. 공공데이터포털 인증키 값은 Codex 대화나 코드에 붙여넣지 않습니다. 프로젝트별 `.env` 파일에 `DATA_GO_KR_SERVICE_KEY=` 형식으로 보관하고, `.env`가 Git에 올라가지 않는지 확인합니다.

## 0. 작업 폴더에서 Codex 열기

```bash
cd vibecoding-codex-book-examples/ch17
codex
```

## 1. 추가할 기능 범위 정하기

```text
지금 국내 시장 대시보드에 사용자에게 유용하지만 범위가 작고 안전한 기능을 하나 추가하려고 해.

조건:
- 구현하지 말고 먼저 현재 코드를 읽고 제안만 한다.
- 외부 로그인, 서버 DB, 매매, 투자 추천은 넣지 않는다.
- 공공데이터포털에서 이미 받아오는 데이터로 만들 수 있어야 한다.
- 브라우저에만 저장해도 되는 기능이면 localStorage 사용 가능 여부를 검토한다.
- 후보 3개를 표로 비교하고, 가장 작은 MVP 하나를 추천해줘.
```

## 2. 관심 종목 기능 추가하기

```text
관심 종목 기능을 추가해줘.

완료 조건:
- 기존 지수 카드, 시장 열기, 업종 히트맵, 종목 순위 구조는 유지한다.
- 화면 상단에 관심 종목 영역을 추가한다.
- 종목명 또는 종목 코드로 검색해 관심 종목에 추가할 수 있게 한다.
- 선택한 종목은 브라우저 localStorage에 저장한다.
- 관심 종목 카드에는 종목명, 시장, 코드, 현재가, 등락률을 표시한다.
- 관심 종목을 해제할 수 있어야 한다.
- 공공데이터포털 수집 실패 시 예시 데이터에서도 기능이 깨지지 않아야 한다.
- 반응형 화면에서 검색창과 카드가 겹치지 않아야 한다.

검증:
- 기존 빌드 명령이 있으면 실행한다.
- 브라우저에서 검색, 추가, 새로고침 후 유지, 해제를 확인한다.
```

## 3. `npm test`를 검증 명령으로 연결하기

```text
이 프로젝트에서 `npm test`가 실행되도록 설정해줘.

조건:
- 지금은 별도 테스트 프레임워크가 없으니 `next build`를 검증 명령으로 연결한다.
- `npm test`를 실제로 실행하고 결과를 보고한다.
- 새 의존성이 필요 없으면 추가하지 않는다.
```

## 4. Stop 훅으로 테스트 실행을 확인하기

```text
Codex Stop 훅을 추가해서, 이번 턴에서 `app`, `lib`, `src` 아래의 표시/계산 소스 파일을 바꿨는데 `npm test` 실행 기록이 없으면 마무리를 막아줘.

완료 조건:
- `hooks.json`에 Stop 훅을 등록한다.
- 훅 스크립트는 `.codex/hooks/verify-tests-before-stop.cjs`에 둔다.
- 같은 턴의 transcript를 읽어 `apply_patch`로 바뀐 소스 파일을 찾는다.
- `.js`, `.jsx`, `.ts`, `.tsx`, `.css`, `.scss`, `.sass` 파일만 검사한다.
- 테스트 파일이나 `__tests__` 폴더는 검사 대상에서 제외한다.
- 같은 턴에 `npm test` 또는 `npm run test`를 실행했으면 통과시킨다.
- 한 턴에서 같은 이유로 무한히 막히지 않게 `.codex/state/`에 상태를 기록한다.
- `.codex/state/`는 Git에 올라가지 않게 한다.

검증:
- 훅 스크립트 문법 오류가 없는지 Node로 실행 가능한 형태인지 확인한다.
- `npm test`를 실행하고 결과를 보고한다.
```
