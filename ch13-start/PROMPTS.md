# 13장 시작 상태 프롬프트

이 폴더는 13장을 **시작하기 직전** 상태다. 빈 폴더에서 `codex`를 실행하고 `/plan`으로 대시보드를 설계해 예시 데이터로 도는 화면까지 받아 둔 결과물이다. 아래 요청문 하나와 `/plan` 문답만으로 만들어졌다.

## 0. 빈 폴더에서 Codex 열기

```bash
mkdir stock-dashboard && cd stock-dashboard
codex
```

## 1. `/plan`으로 대시보드 설계부터 하기

먼저 `/plan`을 단독으로 보내 Plan 모드로 들어간 뒤, 아래 요청문을 그대로 입력한다.

```text
목표:
오늘 국내 주식시장의 분위기와 주요 종목을 한 화면에서 파악하는 대시보드를 만든다.

완료 조건:
- 첫 화면에서 아래 네 가지를 모두 파악할 수 있다.
  - 시장 전반 상태 (KOSPI·KOSDAQ 지수)
  - 오늘 시장이 얼마나 뜨거운지 (시장 열기)
  - 업종별로 어디가 오르고 내렸는지 (업종 히트맵)
  - 등락률·거래대금 상위 종목 (종목 순위)
- 업종 히트맵은 다음 12개 업종을 칸으로 갖는다. 화면에 쓰는 이름 기준이고,
  목록을 임의로 바꾸지 않는다.
  반도체, 자동차, 은행, 증권, 건설, 철강, 운송, 방송통신, 조선, 게임, 2차전지, 화장품
- 첫 화면 배치는 지수 카드와 시장 열기를 한 줄에, 그 아래 업종 히트맵,
  맨 아래 종목 순위로 한다.
- 실제 API 없이도 현실적인 예시 데이터로 화면이 정상 동작한다.

제약:
- 이번 단계에서는 외부 주식 API, 로그인, 실시간 갱신은 하지 않는다.
- 예시 데이터는 나중에 실제 API로 바꾸기 쉬운 구조를 선호한다.
- React + Next.js + Node.js, 기본 JavaScript.

비목표:
- 매매, 관심 종목 저장, 종목 상세, 투자 추천은 이번 범위에 넣지 않는다.

알고 있는 맥락:
- '시장 열기'를 점수로 누를지 표로 펼칠지는 아직 정하지 않았다.
- 업종 히트맵의 색과 타일 모양, 지수 카드와 차트의 세부 구성은 열어 두고 싶다.

지금은 구현하지 말고, 먼저 저장소를 조사하고, 결정이 필요한 것을 한 번에 하나씩 질문으로
정리하고, 위 네 영역을 갖춘 가장 작은 유용한 첫 버전(MVP)을 권장안으로 제안해줘. 추측은
사실로 단정하지 말고 가정으로 표시해줘.
```

## 2. Plan 문답에서 고른 답

Codex는 빈 폴더를 먼저 조사한 뒤(`ls`, `rg --files`, `git status`) 파일을 하나도 만들지 않고, 화면마다 한 문항씩 여덟 번을 물었다. 이 폴더는 아래처럼 답한 결과다. 선택지에 없는 조건은 `tab`으로 메모를 붙여 전달했다.

| 라운드 | 질문 | 고른 답 |
| --- | --- | --- |
| 1 | '시장 열기'를 첫 화면에서 어떤 형태로 보여줄까요? | 점수만 (메모: 점수는 등락률 3% 이상 상승 종목 비율(%) 하나를 그대로 쓴다) |
| 2 | 등락률·거래대금 상위 종목을 어떤 방식으로 구성할까요? | 두 표 나란히 (메모: 상승률·하락률·거래대금 세 칸으로 나란히) |
| 3 | MVP의 화면 크기 대응은 어디까지 포함할까요? | 데스크톱 전용 |
| 4 | 12개 업종 타일을 어떤 방식으로 비교하게 할까요? | 동일 크기 등락률 색상 |
| 5 | KOSPI·KOSDAQ 지수 카드에는 어느 정도 정보를 담을까요? | 핵심 수치 + 미니 차트 |
| 6 | 세 종목 순위는 각각 몇 위까지 보여줄까요? | 5개씩 |
| 7 | MVP의 예시 데이터 시점은 어떻게 표시할까요? | 고정 예시 일시 명시 |
| 8 | 첫 MVP의 기본 화면 테마는 무엇으로 할까요? | 밝은 금융 대시보드 |

요청문이 이미 정한 업종 12개 목록과 첫 화면 배치는 질문으로 되돌아오지 않았고, 계획서에 그대로 반영됐다.

## 3. 계획 확정하고 구현 맡기기

여덟 번째 답을 보내면 Codex가 계획서를 내놓고 곧바로 확인창을 띄운다.

```text
Implement this plan?
› 1. Yes, implement this plan
  2. Yes, clear context and implement
  3. No, stay in Plan mode
```

여기서 **1번**을 골랐다. Codex가 스스로 `Implement the plan.`을 넣고 Default 모드로 돌아가 구현을 시작한다. 승인 요청은 여덟 번 나왔고 모두 1번(Yes)으로 승인했다. `npm install`, 취약점 확인과 패치 버전 설치, `npm run dev` 기동, 화면 확인용 `curl` 순이었다.
