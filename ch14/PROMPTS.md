# 14장 요청문 — 주식 시세 쌓을 데이터베이스, MCP로 연결해 만들기

이 폴더는 14장을 **끝낸 직후** 상태다. `ch13`을 복사한 뒤 아래 순서로 만들었다.
Supabase 가입과 프로젝트 만들기, MCP 승인, `.env`·`.env.sample` 작성은 **사람 몫**이다.

RLS를 켜고 앱의 공개용 키(publishable key)로는 시세를 읽기만 하게 했다. 시세 적재는
Codex의 Supabase MCP로만 한다. 앱에는 시세를 쓰는 경로가 없다.

## 0. 사람 몫 준비 (§14.3)

- supabase.com에서 가입하고 Organization 안에 새 프로젝트를 만든다(이름, Database Password,
  리전). 같은 화면의 Security 칸은 이렇게 둔다.
  - Enable Data API: 켬. 앱이 시세를 읽는 통로다.
  - Automatically expose new tables: 끔. 새 테이블이 저절로 공개되지 않게 하고, 읽기 권한은
    14.4에서 따로 준다.
  - Enable automatic RLS: 켬.
- 프로젝트의 Connect 화면에서 프로젝트 URL과 publishable key를 확인한다.
- Codex 연결 명령은 Supabase 공식 안내(Connect 화면에서 Codex를 고름)에서 가져온다.
  `<프로젝트 ID>`에 방금 만든 프로젝트의 ID를 넣으면 이 연결은 그 프로젝트 하나로 좁혀진다.

```bash
codex mcp add supabase --url "https://mcp.supabase.com/mcp?project_ref=<프로젝트 ID>"
codex mcp login supabase
```

- 브라우저에 권한 승인 화면이 뜨면 조직과 권한을 살펴보고 **사람이 직접** 승인한다.
  이 실행에서는 첫 줄이 등록에 이어 로그인까지 진행했다.
- Codex를 다시 시작하거나 새 세션을 열어 연결을 확인한다. 기본 `/mcp`는 서버마다 한 줄만
  보여 주므로 도구 이름까지 보려면 다음을 입력한다.

```text
/mcp verbose
```

  이 실행에서는 `supabase`가 연결됨(도구 20개), `Auth: OAuth`로 나왔다. Auth 줄이
  `Not logged in`이면 `codex mcp login supabase`로 승인을 마저 끝낸다.
- `.env`에 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 직접 적는다.
  secret key와 service_role 키는 이 앱에 넣지 않는다.
- 이름 세 개(12장의 `DATA_GO_KR_SERVICE_KEY`까지)만 남기고 값은 비운 `.env.sample`을 만든다.
  이 폴더의 `.env.sample`이 그 모양이다. `.gitignore`가 `.env*`처럼 견본까지 막으면 그 아래에
  `!.env.sample` 한 줄을 더한다.

13장의 인증 키 보호 훅이 켜져 있으면 이 뒤로 Codex가 `.env`를 읽으려 할 때마다
`Blocked by hook`을 만날 수 있다. 이 실행에서도 연결을 확인하려고 `.env`를 불러오는 명령이
막혔고, Codex는 우회하지 않고 실제 연결은 아직 확인하지 못했다고 보고했다. 실제 연결은
14.5의 점검과 로그로 확인한다.

## 1. 테이블 설계 (§14.4)

```text
대시보드 데이터를 Supabase에 저장하려고 해. 테이블 구조를 설계해 줘.
요구사항:
- 일별 시세: 종목 코드, 종목명, 기준일, 종가, 등락률, 거래 대금을 저장한다. 같은 기준일의 같은 종목이 두 번 저장되는 일은 구조로 막아야 한다.
- 앱이 쓰는 공개용 키로는 시세를 읽기만 하게 한다. RLS를 켜고 읽기(SELECT) 정책과 읽기 권한만 준다.
- 쓰기(INSERT, UPDATE, DELETE) 정책과 권한은 주지 않는다. 시세 적재는 이 학습용 MCP로만 한다.
- 관심 종목은 localStorage에 남긴다. 사용자 계정과 관심 종목 테이블은 만들지 않는다.
아직 만들지 말고, 테이블 구조와 그렇게 정한 이유부터 보여 줘.
```

이 실행은 `daily_prices` 테이블을 제안했다. 기본 키는 기준일과 종목 코드를 묶은 복합 키였고,
권한 표에는 공개용 키(anon)에 SELECT만 있고 쓰기 정책은 만들지 않는다고 적혀 있었다.
테이블 이름과 키 방식은 실행마다 다를 수 있다. 화면에 필요한 값이 다 있는지, 두 번 저장을
막는 장치가 있는지를 본다.

구조가 요구와 맞으면 테이블을 만들게 한다. 책에는 요청 상자가 없고, 이 실행은 이렇게 보냈다.

```text
좋아, 이 구조로 테이블을 만들어줘. 다 만들면 현재 행 수를 알려줘.
```

바꾸는 도구를 부를 때마다 승인 창이 뜬다. 어떤 호출인지 읽고 허락한다. 보고를 받으면 현재
행 수가 0인지 확인한다.

## 2. 적재와 이중 적재 실험 (§14.4)

```text
오늘 수집한 시세를 방금 만든 일별 시세 테이블에 적재해 줘. 시세는 지금 쓰고 있는 수집 코드로 공공데이터포털에서 받은 실제 값이어야 하고, 임의로 만든 값을 넣으면 안 돼. 끝나면 행이 몇 개인지 알려 줘. 그다음 같은 데이터를 한 번 더 적재하고, 행 수가 어떻게 됐는지 다시 알려 줘.
```

두 번째 적재 뒤에도 행 수가 그대로면 성공이다. 이 실행은 두 번 모두 2,867행이었다
(기준일 2026-10-15). 적재한 시세는 Supabase에만 있고 이 폴더에는 없다.

## 3. 화면을 데이터베이스에서 읽게 하기 (§14.5)

```text
이제 대시보드가 Supabase를 읽게 바꾸자.
- 관심 종목은 지금처럼 localStorage에서만 읽고 써 줘.
- 시세는 앞에서 만든 일별 시세 테이블의 최신 기준일 데이터를 읽어 보여 주고, 그 기준일을 화면에 함께 표시해 줘.
- NEXT_PUBLIC_SUPABASE_URL과 NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY를 사용해.
- 지수 카드, 시장 열기, 업종 히트맵은 Supabase에 없으니 지금처럼 기존 API로 채워 줘. Supabase에서 읽는 것은 종목 시세뿐이야.
- 앱에는 시세를 추가·수정·삭제하는 경로를 만들지 마.
- Supabase에 데이터가 없거나 읽기에 실패하면 기존 API를 호출하고, 그것도 실패할 때만 예시 데이터와 안내를 보여 줘.
```

이 폴더를 만든 실행은 넷째 줄(지수 카드·시장 열기·업종 히트맵) 없이 보냈고, Codex가 테이블에
없는 세 영역을 ‘데이터 없음’으로 바꿨다. 다음 요청으로 되돌렸다. 책에는 이 일을 막으려고
요청문에 넷째 줄을 넣었다.

```text
지수 카드, 시장 열기, 업종 히트맵은 Supabase에 없더라도 지금처럼 기존 API 경로로 계속 채워줘.
Supabase에서 읽는 것은 종목 시세만이야. 화면 네 영역 구조는 그대로 유지해줘.
```

## 4. 전환 후 점검 (§14.5)

다섯 가지를 확인한다. 앞의 넷은 사람이 브라우저로 본다.

```text
전환 후 점검:
[ ] 일반 창의 관심 종목이 그대로 남아 있다.
[ ] 시크릿 창의 관심 종목은 비어 있다.
[ ] 두 창의 시세가 같은 기준일을 보여 준다.
[ ] 화면에 시세의 기준일이 표시된다.
[ ] 공개용 키로 시세를 추가하려 하면 거부된다.
```

앞의 둘은 관심 종목이 브라우저별 개인 설정으로 남았다는 증거이고, 그다음 둘은 화면이 같은
기준일의 시세를 보여 준다는 표시다. 마지막 항목은 Codex에게 맡긴다.

```text
전환 후 점검 마지막 항목이야. 시세 테이블에 앱이 쓰는 publishable key 경로로 쓰기(INSERT)를 한 번 시도해서 거부되는지 확인해 줘. MCP 말고 앱 키 경로로만 시험해. 거부되는 게 정상이야. 결과만 알려 줘.
```

이 실행에서는 HTTP 401과 함께 `permission denied for table daily_prices`가 돌아왔고, 데이터는
추가되지 않았다.

정말 데이터베이스에서 읽었는지는 Supabase 대시보드의 Logs에서 확인한다. API Gateway를 고르고
검색 칸에 `/rest/v1`을 넣으면 앱이 시세를 읽은 요청(GET 200)과 방금 공개용 키로 시도한
쓰기(POST 401)가 보인다. 적재는 MCP가 데이터베이스에 직접 넣었으므로 이 목록에 나오지 않는다.

## 참고 — 책에 없는 선택 단계

적재를 마친 뒤 MCP 주소 끝에 `&read_only=true`를 붙여 다시 등록하면, 그 뒤로 Supabase MCP로는
읽기만 된다. 주소가 바뀌면 로그인이 풀리므로 `codex mcp login supabase`를 다시 한다. 이 폴더를
만든 실행에서는 하지 않았다.
