이 프로젝트를 배포한 뒤 그 결과를 최종 검증하는 Skill을 만들어 줘. 이름은 verify-market-dashboard이야. 이 저장소에서만 쓰는 Skill로, 저장소 루트의 .agents/skills/verify-market-dashboard/에 저장해 줘. 그 경로에 쓸 수 없으면 다른 위치로 우회하거나 AGENTS.md를 고치지 말고, 쓰기 승인을 요청하거나 멈춰서 알려 줘. SKILL.md와 보고서는 한국어로 작성해 줘. 다음 순서로 읽기 전용 검증을 수행해야 해.

## 2. 훅에 막혔을 때: 검사 범위 좁히기 (§16.3)

13장의 훅을 걸어 둔 저장소라면 Skill 문서를 쓰는 명령이 `Blocked by hook`으로 막힐 수 있다.
Skill 문서에는 `.env`라는 글자가 자주 들어가는데, 훅이 이 글자까지 넓게 잡기 때문이다.
10/17 실행에서는 폴더는 승인을 받아 만들었지만 `SKILL.md`를 쓰는 명령이 막혀, Codex가 우회하지
않고 멈춘 채 보고했다.

훅은 자기 파일을 고치는 명령도 같은 이유로 막으므로 잠시 끈다. `/hooks`에서 PreToolUse를 열고
13장에서 만든 인증 키 보호 훅을 고른 뒤 [Space]로 끈다(앞의 `[x]`가 `[ ]`로 바뀐다).
그리고 **막힌 그 대화에서** 이어서 요청한다.

```text
방금 Skill 파일을 쓰는 명령이 인증 키 보호 훅에 막혔어. 훅의 검사 범위를 좁혀 줘.
- .env 파일을 직접 읽거나 여는 명령과 .env 파일을 고치는 시도는 지금처럼 막는다.
- 문서 내용, 커밋 메시지, 검색 조건처럼 .env라는 이름을 적기만 하는 것은 막지 않는다.
- 실제 키 값이 명령이나 코드에 나타나면 막는 검사는 그대로 둔다.
시험은 훅 스크립트에 예시 입력을 넣어서만 하고 실제 .env는 열지 마. 방금 막힌 명령이 통과하는지도 시험해서 결과를 표로 보여 줘.
```

이 실행에서 Codex는 `.env` 직접 읽기·수정과 가짜 키 값은 계속 막고, 문서와 커밋 메시지·검색
조건의 언급은 통과시키는지 예시 38개로 시험했다. 새 대화에서 같은 부탁을 한 두 번은 막혔던
명령을 몰라, 고친 훅이 문서 쓰기나 커밋 메시지를 여전히 막았다.

결과를 확인했으면 `/hooks`에서 훅을 바로 다시 켠다. 훅 스크립트만 바뀐 것은 `/hooks`가 다시
묻지 않으므로 고친 내용은 Diff로 직접 읽는다. Skill이 아직 만들어지지 않았다면 다시 만들어
달라고 요청한다. 이 실행은 이렇게 보냈다.

```text
훅을 다시 켰어. 아까 요청한 대로 Skill을 다시 만들어줘.
```

## 3. SKILL.md 검토 (§16.3)

`/mention`으로 `SKILL.md`를 붙인 뒤 요청한다.

```text
이 SKILL.md를 검토해 줘.
- 언제 사용하고 언제 사용하지 않는지가 description에 분명한지
- 배포 상태·배포 화면·로그·환경 변수·Git 비밀 검사 다섯 가지가 순서대로 있는지
- 보고서의 다섯 행 표 형식과 행 이름이 파일에 고정돼 있는지
- 비밀 값 조회나 자동 수정 같은 위험한 동작이 없는지
- 확인하지 못한 항목을 PASS로 처리하지 않는지
문제가 있으면 파일을 고치지 말고 위치와 이유만 알려 줘.
```

description에 언제 쓰지 않는지가 빠져 있다면 “기능 구현, 자동 수정, 실제 배포, 환경 변수 값
조회에는 사용하지 않는다.”처럼 한 문장 보태게 하고, 고쳐진 파일을 다시 읽어 확인한다.
이 실행의 description에는 ‘배포나 코드 수정에는 사용하지 않는다.’가 처음부터 들어 있어 검토는
문제없음으로 돌아왔다. 보정 요청으로 ‘로컬 개발 점검이나 배포 전 테스트에는 사용하지 않는다.’가
더해졌다.

## 4. 커밋하고 푸시하기 (§16.3)

검토를 마쳤으면 만든 Skill을(훅을 고쳤다면 그 변경도 함께) 커밋하고 푸시한다. Skill은 저장소의
최신 커밋이 프로덕션에 걸려 있는지부터 확인하므로, 푸시하지 않으면 첫 칸부터 BLOCKED가 나온다.
책에는 요청 상자가 없다. 이 실행은 훅 수정과 Skill을 한 커밋으로 올렸고, 이렇게 보냈다.

```text
훅 수정과 검증 Skill을 커밋하고 푸시해줘.
```

TIP: 푸시했는데 Vercel 배포가 Blocked로 멈추면, 내 컴퓨터 Git에 적힌 이메일
(`git config user.email`)이 GitHub 계정에 등록된 이메일과 같은지 확인한다. 무료 요금제(Hobby)에서는
계정 주인이 만든 커밋만 배포된다. 이 실행에서도 이 일로 한 번 막혀, 이메일을 고치고 다시 배포했다.

## 5. Skill 호출 (§16.4)

`/skills`나 입력창의 `$`에서 `verify-market-dashboard`를 고르고 요청문을 붙인다.

```text
$verify-market-dashboard
```

```text
현재 주식 대시보드가 제대로 배포됐는지 최종 검증해 줘. 파일과 외부 설정은 바꾸지 말고 결과만 보고해 줘.
```

이 실행의 보고는 전체 WARNING이었다.

```text
전체: WARNING

| 영역 | 상태 | 확인한 근거 | 다음 행동 |
| --- | --- | --- | --- |
| 배포 상태 | PASS | 로컬·원격의 최신 커밋과 배포 커밋 일치, 최신 프로덕션 Ready | 없음 |
| 배포 화면·API | WARNING | 조회 도구가 인증 우회 링크를 만들 수 있어 읽기 전용 조건상 쓰지 않음. 실제 시세·출처·기준일 미확인 | 같은 주소에서 주요 영역과 실제 조회를 사람이 확인 |
| 런타임 로그 | WARNING | 최근 60분 조회는 보존 기간 오류, 30분 재조회는 로그 없음 | 최근 60분 로그와 화면 요청을 함께 확인 |
| 환경 변수 계약 | WARNING | 코드가 요구하는 세 이름은 계약(.env.sample·README·기준 문서)과 일치. README 첫머리의 설명이 지금 코드와 어긋남 | 문서를 정리한 뒤 다시 검증 |
| Git 비밀 검사 | PASS | 추적 파일과 커밋 이력에 환경 파일·비밀 값 없음(후보 1건은 테스트용 문자열) | 없음 |
```

화면과 로그 두 칸은 확인하지 못한 칸이다. 15장에서 잠근 주소를 열려면 잠금을 잠시 우회하는
링크를 만들어야 하는데, ‘외부 설정은 바꾸지 말고’라는 조건대로 열지 않았다. 무료 요금제는 로그를
한 시간만 보관해 60분 조회가 실패했다. 두 칸은 사람이 잇는다. 내 브라우저로 주소를 열어 출처와
기준일, 실제 시세를 보고, 그다음 로그를 다시 본다.

환경 변수 계약 칸은 이름 세 개가 맞았는데도 WARNING이다. 이 폴더의 `README.md` 첫머리가 아직
12장 시작 상태(예시 데이터로 도는 대시보드)를 설명하고 있기 때문이다. README는 18장에서 다음
사람이 읽을 문서로 고쳐 쓴다.

## 6. 일부러 문제 하나를 심어 시험하기 (§16.5)

다음 한 줄을 서버 코드에 넣고 커밋하는 일도 Codex에게 맡긴다.

```text
서버 코드 아무 파일에 다음 한 줄만 추가하고 커밋해 줘. 다른 코드는 건드리지 마.
```

```js
const supabasePublishableKeyPreview = process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEI;
```

`$verify-market-dashboard`를 같은 요청문으로 다시 실행하면 두 칸이 BLOCKED가 된다. 이 실행에서는
배포 상태가 BLOCKED(최신 프로덕션은 Ready지만 배포 커밋이 저장소의 최신 커밋과 다름), 환경 변수
계약이 BLOCKED(`lib/supabaseMarketData.js`가 계약에 없는 `…_KEI`를 참조, 계약은 `…_KEY`)였다.

확인했으면 실험 커밋을 되돌리고 푸시한다. 되돌리기도 Codex에게 `git revert`로 맡긴다.
이 실행은 이렇게 보냈다.

```text
확인했어. 방금 심은 실험 커밋을 git revert로 되돌리고 푸시해줘.
```

되돌린 커밋이 배포된 뒤 Skill을 한 번 더 돌리면 두 칸의 BLOCKED가 풀린다. 이 폴더는 되돌린
뒤의 상태라 그 한 줄이 없다.
