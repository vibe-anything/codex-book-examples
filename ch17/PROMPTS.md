# 17장 요청문 — 깃 워크트리와 서브 에이전트로 두 기능을 동시에 만들기

이 폴더는 17장을 **끝낸 직후** 상태다. `ch16`(검증 Skill까지 끝낸 상태)을 복사한 뒤
아래 요청 하나로 두 기능을 병렬로 만들고 합쳤다. 대시보드의 원래 작업 폴더에서 연 Codex
세션에서 요청한다.

이 폴더의 검증 Skill은 `ch16`과 같은 판(10/18에 고친 요청문으로 만든 것)으로 맞췄다. 이 장을
실행한 10/17에는 그 전 판이었지만, 17장 작업은 Skill을 건드리지 않는다.

## 1. 두 기능 병렬 요청 (§17.2)

```text
대시보드에 두 기능을 동시에 만들어 줘.
만들 것
- 종목 비교: 서로 다른 두 종목의 현재가와 오늘 등락률을 나란히 보여 주고, 선택을 기억한다. 같은 종목을 고르면 다른 종목을 고르도록 알려 준다.
- 다크 모드: 처음에는 컴퓨터 화면 설정을 따르고, 내가 고른 화면 모드를 기억한다. 모든 카드와 상승·하락 정보는 두 화면에서 또렷하게 보여 주고, 색과 부호로 함께 구분한다.
진행
- 먼저 지금 작업을 잃을 위험이 없는지 확인해 줘. 저장하지 않은 변경이 있으면 임의로 커밋하거나 stash하지 말고 상태만 알려 줘.
- 안전하면 기능마다 별도 깃 워크트리와 서브 에이전트 한 명을 배정해 병렬로 구현해 줘.
- 깃 워크트리는 프로젝트 폴더 안에 만들고, 어디에 만들었는지 경로를 알려 줘.
- 각 서브 에이전트에게 작업 경로·브랜치·수정 범위를 알려 주고, 올바른 작업장인지 확인한 후 시작하게 해 줘.
- 작업장을 만들거나 검사를 준비하는 데 권한이 필요하면 포기하지 말고 승인을 요청해 줘.
- 별도 작업장에 쓸 권한이 없으면 같은 폴더에서 진행하지 말고 멈춰서 알려 줘.
완료
- 각 서브 에이전트가 맡은 범위만 예시 데이터로 검사해 커밋하게 해 줘.
- 둘 다 통과하면 시작점 대비 각 변경을 검토하고 하나씩 합쳐줘. 충돌이나 제품 결정이 필요하면 현재 병합을 중단하고 알려 줘.
- 홈과 비교 화면의 두 모드, 기존 기능, 자동 검사와 빌드까지 확인해 줘.
- 두 서브 에이전트의 실행 구간이 실제로 몇 초 겹쳤는지, 시작 커밋과 최종 결과 사이의 Diff 요약, 최종 주소를 보여 줘.
- push·배포·작업장 정리는 하지 마.
```

이 폴더를 만든 실행은 ‘진행’ 첫 줄의 둘째 문장(저장하지 않은 변경은 상태만 알려 달라는 말) 없이
보냈다. 작업 트리가 깨끗해서 결과는 같다.

이 실행의 결과:

- 메인 Codex가 작업 트리가 깨끗한지 확인하고 시작 커밋을 적은 뒤, 프로젝트 폴더 안에 깃 워크트리
  두 곳(`.worktrees/stock-comparison`, `.worktrees/dark-mode`)과 브랜치를 만들어 서브 에이전트를
  한 명씩 보냈다. 비교 화면은 새 주소(`/compare`), 다크 모드는 공통 레이아웃과 색을 맡았다.
- 승인 창은 16번 떴다. 두 작업장 모두 설치와 빌드를 준비하느라 승인을 여러 번 요청했다.
- 두 작업이 각자 검사와 빌드를 통과해 커밋한 뒤 충돌 없이 하나씩 합쳐졌다. 통합 테스트는 69개다.
- 두 서브 에이전트가 겹쳐 돈 시간은 약 66초, Diff 요약은 13개 파일에 +357/−14줄이었다. 최종 주소는
  예시 데이터로 띄운 로컬 서버였다.
- 깃 워크트리 폴더가 Git 추적과 린트에 섞이지 않게 `.gitignore`와 린트 설정에서 `.worktrees/`를 뺐다.

## 2. 충돌이 나면 (§17.2)

Codex가 병합을 멈추고 충돌 파일을 보고하면, 어느 쪽을 기준으로 합칠지 정해 보낸다. 이 실행은
충돌이 나지 않아 쓰지 않았다.

```text
충돌한 파일마다 두 작업이 각각 무엇을 바꾸려 했는지 설명해 줘. 두 기능이 모두 살아 있게 합치고, 공통 색상이 갈리면 다크 모드 작업을 기준으로 맞춰 줘. 합친 후에는 전체 검사를 다시 돌려서 결과를 알려 줘.
```

`.env`처럼 커밋하지 않은 파일은 새 작업장에 따라가지 않는다. 다만 원래 폴더의 `.env`는 그대로
있어 서브 에이전트가 찾아 읽을 수도 있으므로, 인증 키 접근이 저절로 막히지는 않는다. 그래서
요청문에서 각 작업장의 검사를 예시 데이터로 하도록 정해 두었다.

## 3. 작업장 정리 (§17.3)

합친 제품을 홈과 비교 화면, 두 모드에서 직접 확인한 뒤 보낸다.

```text
최종 결과를 확인했어. 합친 커밋이 원래 프로젝트에 남아 있는지 다시 확인하고, 이번 작업에 만든 깃 워크트리와 작업용 브랜치만 안전하게 정리해 줘.
```

이 실행에서는 병합 커밋이 남았는지 확인한 뒤 워크트리 두 곳과 작업용 브랜치만 지웠다.
