# 15장 프롬프트 모음

아래 요청문은 `vibecoding-codex-book-examples/ch15` 폴더에서 `codex`를 실행한 뒤, 장의 흐름에 맞춰 하나씩 복사해 붙여넣습니다.

이 장은 14장까지 localStorage에 두던 관심 종목과 수집한 일별 시세를 Supabase로 옮깁니다. Supabase 가입과 프로젝트 만들기, 그리고 URL·anon key를 `.env`에 넣는 일은 사람이 직접 합니다. 키 값은 Codex 대화나 코드에 붙여넣지 않습니다.

## 0. Supabase MCP 연결 (터미널)

프로젝트의 Connect 화면이 안내하는 명령 두 줄입니다. `<프로젝트 ID>`는 프로젝트 홈에서 확인합니다.

```bash
codex mcp add supabase --url "https://mcp.supabase.com/mcp?project_ref=<프로젝트 ID>"
codex mcp login supabase
```

연결 확인은 Codex 안에서 `/mcp`를 입력해 supabase 아래 도구 목록이 보이는지로 합니다.

## 1. 테이블 구조 설계 맡기기 (아직 만들지 않음)

```text
대시보드 데이터를 Supabase에 저장하려고 해. 테이블 구조를 설계해줘.

요구사항:
- 일별 시세: 종목코드, 종목명, 기준일, 종가, 등락률, 거래대금을 저장한다.
  같은 기준일의 같은 종목이 두 번 저장되는 일은 구조로 막아야 한다.
- 관심 종목: 지금 localStorage에 있는 관심 종목을 저장한다.
- 이 대시보드는 로그인 없는 1인용 도구다. 사용자 계정이나 user_id 같은
  다인용 설계는 넣지 않는다.
- 아직 만들지 말고, 테이블 구조와 그렇게 정한 이유부터 보여줘.
```

구조가 요구와 맞으면(중복을 막는 장치가 들어 있으면) 테이블을 만들게 합니다. 테이블·컬럼 이름은 실행마다 조금 다를 수 있으니 화면에 나온 이름을 그대로 씁니다.

## 2. 일부러 두 번 적재해 정합성 확인하기

```text
오늘 수집한 시세를 daily_stock_prices 테이블에 적재해줘.
시세는 13장부터 쓰던 수집 코드로 공공데이터포털에서 받은 실제 값이어야 하고,
임의로 만든 값을 넣으면 안 돼. 끝나면 행이 몇 개인지 알려줘.
그다음 같은 데이터를 한 번 더 적재하고, 행 수가 어떻게 됐는지 다시 알려줘.
```

두 번째 적재 뒤에도 행 수가 그대로면 성공입니다. Supabase 대시보드의 Logs 화면에서 적재 요청이 기록으로 남았는지도 확인합니다.

## 3. 화면을 데이터베이스에서 읽게 하기

```text
이제 대시보드가 Supabase를 읽게 바꾸자.
- 관심 종목은 localStorage 대신 watchlist_stocks 테이블에서 읽고 써줘.
- 시세는 데이터베이스에 있는 최신 기준일 치를 먼저 쓰고, 없을 때만 API를 불러줘.
- Supabase URL과 anon key는 .env에서 읽어 서버 쪽 코드에서만 써줘.
  브라우저에 내려보내면 안 돼.
```

시크릿 창에서 대시보드를 다시 열어 관심 종목이 남아 있는지, 안내 문구가 'Supabase daily_stock_prices 기준'으로 바뀌었는지 확인합니다.

## 4. 통로 잠그기 (터미널)

만들 것이 끝나면 `~/.codex/config.toml`의 supabase `url` 끝에 `&read_only=true`를 붙입니다. 주소가 바뀌면 로그인이 풀리므로, 한 번 다시 로그인해 잠긴 통로를 엽니다.

```bash
codex mcp login supabase
```
