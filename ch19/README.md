# 한국 주식 시장 대시보드

KOSPI·KOSDAQ의 일별 지수와 종목 시세를 한 화면에서 확인하는 Next.js 대시보드다. 이 README는 현재 운영 방법과 제품 결정의 기준 문서다. `PROMPTS.md`는 18~19장의 작업 과정을 남긴 기록이므로, 둘이 다르면 현재 구현을 확인한 뒤 이 문서를 우선 갱신한다.

## 현재 구현

- 일별 시장 지수, 시장 열기, 검증된 업종 지수, 종목 순위를 보여준다.
- 관심 종목은 Supabase 프로젝트의 공유 목록으로 저장한다.
- 비교할 두 종목과 밝은·어두운 화면 모드 선택은 각 브라우저에 저장한다.

## 처음 받았을 때: 실행까지 3단계

Node.js 20.9 이상이 필요하다.

1. 의존성을 설치한다.

   ```bash
   npm ci
   ```

2. 환경변수 파일을 만들고 세 값을 채운다.

   ```bash
   cp .env.sample .env
   ```

   `.env`의 `DATA_GO_KR_SERVICE_KEY`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`에 기존 프로젝트의 값을 넣는다. 실제 값은 채팅, 문서, 코드, 커밋에 남기지 않는다.

3. 개발 서버를 실행한다.

   ```bash
   npm run dev
   ```

   브라우저에서 `http://localhost:3000`을 연다. 실제 데이터 대신 `예시 데이터` 안내가 보이면 아래의 연결, 환경변수, 데이터 기준일을 먼저 점검한다.

## 다시 이어야 할 외부 연결

### Supabase

앱 런타임 연결과 AI 작업용 MCP 연결은 별개다. MCP를 연결해도 `.env`가 자동으로 채워지지 않는다.

- 앱은 기존 Supabase 프로젝트의 `daily_stock_prices`, `watchlist_stocks` 테이블을 사용한다.
- 새 세션에서는 기존 프로젝트를 확인한 뒤 Supabase MCP를 먼저 읽기 전용으로 연결한다. `<project-ref>`나 계정 식별자는 저장소에 기록하지 않는다.

  ```bash
  codex mcp add supabase --url "https://mcp.supabase.com/mcp?project_ref=<project-ref>&read_only=true"
  codex mcp login supabase
  codex mcp list
  ```

- 이 저장소에는 Supabase 마이그레이션과 일별 적재 작업이 없다. 기존 프로젝트를 새 프로젝트로 착각해 다시 만들지 말고, 테이블과 최신 적재일을 확인한다.
- `daily_stock_prices`에서 사용하는 열은 `trade_date`, `stock_code`, `stock_name`, `market`, `close_price`, `change_rate`, `turnover`다.
- `watchlist_stocks`에서 사용하는 열은 `stock_code`, `sort_order`, `created_at`이다. 로그인 기능이 없으므로 현재 관심 종목 목록은 사용자별 목록이 아니라 해당 프로젝트가 공유하는 목록이다.

### Vercel

Vercel 연결 정보가 들어 있는 `.vercel/`은 의도적으로 Git에서 제외한다. 새 컴퓨터나 새 AI 세션에서는 기존 배포를 소유한 올바른 계정·팀과 프로젝트에 다시 연결해야 한다.

```bash
codex mcp add vercel --url https://mcp.vercel.com
codex mcp login vercel
codex mcp list
```

CLI 작업이 필요하면 `npx vercel login` 후 `npx vercel link`로 **기존 프로젝트**를 선택한다. 같은 이름의 새 프로젝트를 만들지 않는다. Production 환경에도 `.env.sample`과 같은 세 키가 각각 등록되어 있어야 하며, 값은 조회하거나 문서에 복사하지 않는다.

## 환경변수 계약

`.env.sample`에는 아래 키 이름만 두고 값은 항상 비워 둔다.

| 키 | 용도 |
| --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 일반 인증키. 서버에서만 사용한다. |
| `SUPABASE_URL` | 기존 Supabase 프로젝트 URL |
| `SUPABASE_ANON_KEY` | 기존 Supabase 프로젝트의 anon key. service role key를 대신 넣지 않는다. |

키를 추가하거나 이름을 바꾸면 코드, `.env.sample`, Vercel 환경변수 계약을 같은 변경에서 함께 갱신한다. `.env`, `.env.local`, Vercel 값, Supabase 비밀 값은 커밋하지 않는다.

## 데이터의 성격

### 출처와 우선순위

공공 시세 원천은 금융위원회 공공데이터포털 OpenAPI다.

- [지수시세정보](https://www.data.go.kr/data/15094807/openapi.do): KOSPI·KOSDAQ 지수와 검증된 업종 지수
- [주식시세정보](https://www.data.go.kr/data/15094808/openapi.do): KOSPI·KOSDAQ 종목의 종가, 등락률, 거래대금
- [상장종목정보](https://www.data.go.kr/data/15094775/openapi.do): 종목 코드 검증

세부 API 필드와 화면별 처리 근거는 확인일을 적은 `API_CHECK.md`에 남긴다. 데이터 원천이나 업종 매핑을 바꿀 때는 공식 문서를 다시 확인하고 확인일과 결정 기록을 함께 갱신한다.

화면은 먼저 Supabase `daily_stock_prices`의 최신 적재일 종목 시세와 공공데이터포털 지수를 조합한다. Supabase가 없거나 실패하면 공공데이터포털의 주식시세·상장종목정보를 직접 조회한다. 업종 하나에 맞는 공식 지수가 없으면 해당 타일만 빼며, 이를 0%나 수집 실패로 표시하지 않는다. 전체 수집 경로가 실패했을 때만 실패 이유를 붙인 명시적 예시 데이터로 전환한다.

### 갱신 시점과 휴장일

이 데이터는 장중 실시간 시세가 아니다. 공공데이터포털 안내 기준으로 한 거래일의 시세는 다음 영업일 13시 이후 제공될 수 있다. 금요일 데이터는 통상 월요일에, 월요일이 휴일이면 그다음 영업일에 갱신된다.

주말·공휴일·임시 휴장일에는 해당 날짜의 행이 비어 있는 것이 정상이다. 앱은 최신으로 제공된 기준일을 찾아 표시하므로 휴장일에는 직전 거래일 데이터가 보일 수 있다. 지수와 종목의 최신 기준일이 다를 수 있어 화면에도 두 날짜를 따로 표시한다.

## 계산 기준

`시장 열기`에는 외부의 별도 지표나 임의 가중 점수를 사용하지 않는다. 현재 화면이 정의한 상승 기준인 **등락률 3% 이상 종목 수 ÷ 전체 유효 종목 수 × 100**을 계산하고, 그 상승 종목 비율을 그대로 표시한다. 임계값은 `lib/marketData.js`의 `STRONG_GAIN_THRESHOLD`와 화면 문구가 항상 일치해야 한다.

지수 카드의 상승·하락·보합 수는 해당 시장 종목의 등락률이 각각 `> 0`, `< 0`, `= 0`인지 집계한 값이다. 관심 종목과 비교 화면의 등락률은 개인 수익률이 아니라 해당 거래일의 시세 등락률이다.

## 결정 기록

아래 결정은 빈 화면을 임의의 숫자로 그럴듯하게 채우지 않고, 이 대시보드가 실제로 아는 범위를 분명히 하기 위한 것이다.

| 결정 | 이유와 유지 규칙 |
| --- | --- |
| 조선·게임·2차전지는 공식 TOP 10 테마지수로 표시한다. | 2026-07-19 공공데이터포털 최신 응답에서 `KRX 조선 TOP10 지수`, `KRX 게임 TOP 10 지수`, `KRX 2차전지 TOP 10 지수`를 확인해 정확히 매핑했다. 세 타일은 출처를 `테마지수`로 표시하며, 전체 상장사를 포괄하는 산업분류 지수로 표현하지 않는다. |
| 화장품은 히트맵에서 제외한다. | 같은 응답 전체에서 화장품·뷰티·코스메틱에 해당하는 지수명을 확인하지 못했다. 관련 데이터가 어디에도 없다는 뜻은 아니며, 이름이 비슷한 소비재 지수나 만든 값으로 대신하지 않는다. |
| 보유 종목 수량과 개인 수익률은 넣지 않는다. | 실제 계좌 연동 없이는 매입가·수량·수익률이 모두 가짜 숫자가 된다. 현재 관심 종목은 관찰 목록일 뿐 보유 자산이 아니다. |
| 종목 비교는 두 종목까지만 허용한다. | 한 화면에서 두 종목을 나란히 읽는 것이 기능의 목적이다. 세 종목 이상은 레이아웃과 제품 목적을 다시 결정할 때만 확장한다. |
| `예시 데이터` 안내를 지우거나 실제 데이터처럼 꾸미지 않는다. | 이 문구는 전체 수집 실패를 사용자에게 알리는 안전장치다. 개별 누락 업종을 채우는 용도가 아니며, 실패 이유와 함께 보여야 한다. 배포 검증에서 이 안내가 보이면 정상 실데이터 상태가 아니라 `WARNING`이다. |

로그인, 결제, 실제 증권 계좌 연동, 매매, 투자 추천은 이 프로젝트의 범위 밖이다.

## 알려진 한계

- 공공데이터포털 개발계정은 각 API 페이지에서 기본 호출 한도를 안내한다. 현재 안내되는 개발 트래픽은 10,000건 수준이지만 정책과 승인 상태가 바뀔 수 있으므로 운영 전 포털에서 다시 확인한다.
- 페이지는 동적·무캐시로 데이터를 읽는다. Supabase 종목 시세가 있더라도 지수 조회가 발생하고, Supabase fallback 경로에서는 주식·상장종목 API도 추가로 호출하므로 새로고침이 많으면 한도를 빠르게 쓸 수 있다.
- 공공 API 조회는 큰 첫 페이지를 요청하며 별도 페이지네이션이 없다. 제공 종목 수가 요청 크기를 넘으면 일부가 빠질 수 있다.
- 조선·게임·2차전지는 전체 업종 종목을 포괄하는 산업분류 지수가 아니라 각 분야의 10종목으로 구성된 공식 테마지수다.
- Supabase에 행이 있으면 공공 원천의 최신 날짜와 비교하지 않고 그중 가장 최신 적재일을 우선한다. 적재 작업이 멈추면 오래된 데이터가 계속 보일 수 있다.
- 저장소에는 Supabase 스키마 마이그레이션, seed, 정기 수집 스케줄러, 백업 절차가 없다.
- 로그인과 `user_id`가 없어서 관심 종목은 사용자별로 분리되지 않는다.
- 실시간 개장 여부, 장중 가격, 초 단위 갱신, 외국인·기관 수급은 현재 원천과 범위로 제공하지 않는다.

## 되돌리는 법

### 코드

먼저 작업 소유권과 범위를 확인한다.

```bash
git status --short
git log --oneline -n 10
```

공유된 커밋은 이력을 지우지 말고 `git revert <commit-sha>`로 되돌린다. 커밋하지 않은 파일은 다른 사람의 작업이 아님을 확인한 뒤에만 `git restore -- <path>`를 사용한다. `git reset --hard`로 다른 작업을 함께 지우지 않는다.

이 디렉터리가 아직 Git에서 `untracked`라면 되돌릴 기준 커밋이 없는 상태다. 먼저 검토한 초기 인수인계 커밋을 만들어야 이후 변경에 `git revert`를 사용할 수 있다. 되돌린 뒤에는 아래 검증을 모두 통과시키고 그 커밋을 배포한다.

```bash
node --test lib/*.test.js
npm test
```

### Vercel 배포

잘못된 Production 배포가 노출되면 올바른 계정·팀·프로젝트인지 먼저 확인하고, Vercel 대시보드의 Production 배포에서 **Instant Rollback**을 선택하거나 다음 명령을 사용한다.

```bash
npx vercel rollback <deployment-url-or-id>
npx vercel rollback status
```

[Vercel의 Production 롤백 안내](https://vercel.com/docs/deployments/rollback-production-deployment)에 따라 대상과 상태를 확인한다. 롤백은 이전 빌드로 트래픽을 돌릴 뿐 Git, Supabase 데이터, 환경변수를 되돌리지 않는다. 이후 새 배포를 Production으로 다시 승격해야 한다면 검증을 마친 배포에 `npx vercel promote <deployment-url-or-id>`를 사용한다. 롤백 또는 재승격 뒤에는 `verify-market-dashboard` Skill로 실제 화면·API·로그·환경변수 계약을 다시 확인한다.

Supabase 스키마나 데이터 변경은 코드·Vercel 롤백과 별개다. 해당 프로젝트의 마이그레이션과 백업을 확인해 별도로 복구하며, 백업이 없으면 추측으로 데이터를 덮어쓰지 않는다.

## 남은 일

- 화장품에 같은 의미로 쓸 수 있는 공식 데이터가 새로 제공되는지 조사한다.
- Supabase 일별 시세 적재를 자동화하고, 공공 원천과 기준일을 비교해 stale 상태와 휴장일을 구분한다.
- Supabase 마이그레이션, 최소 seed, RLS, 백업·복구 절차를 저장소에 남긴다.
- 데이터 요청 캐시·재검증 주기·호출 실패 재시도를 설계해 API 한도 소모를 줄인다.
- 화면에 데이터 지연과 각 원천의 기준일을 더 명확하게 알린다.
- 업종 누락, 전체 fallback, 서로 다른 기준일, 휴장일을 고정 fixture로 검증하는 회귀 테스트를 보강한다.
- 미뤄 둔 종목 상세 화면을 설계한다.
- 필요하다면 사용자가 저장한 화면 모드를 지우고 다시 “컴퓨터 설정 따르기”로 돌아가는 선택지를 추가한다.

로그인·결제·실제 계좌 연동은 남은 일 목록이 아니라 명시적인 범위 밖이다.

## 검증 빠른 참조

코드를 바꾸면 먼저 다음 명령을 실행한다. `npm test`는 이 프로젝트에서 단위 테스트가 아니라 Production 빌드 검증이다.

```bash
node --test lib/*.test.js
npm test
```

다른 사람에게 공유하거나 배포 상태를 인계하기 전에는 `verify-market-dashboard` Skill을 읽기 전용으로 실행하고 `PASS`·`WARNING`·`BLOCKED` 결과를 함께 남긴다.
