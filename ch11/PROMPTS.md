# 11장 요청문 — 서브 에이전트 활용하기

이 폴더는 11장을 **끝낸 직후** 상태다. `ch10`을 복사한 뒤 아래 순서로 만들었다. 같은 일을 세 방식으로
맡겨 비교하므로, 방식마다 같은 출발선에서 시작한다. 실제 API를 부르므로 `.env`에 자기 인증 키가
있어야 한다.

## 1. 메인 에이전트가 직접 구현한 결과 보기 (§11.3)

`/status`로 시작 상태를 본 뒤 되돌아올 지점부터 남긴다.

```text
/status
```

```text
비교 실험을 시작하기 전에 지금 상태를 커밋으로 남겨 줘.
```

`.git` 폴더에 쓰는 명령이라 승인 창이 뜰 수 있다. 출발선을 남기는 일이므로 허용한다.

```text
자동 완성 기능을 구현해 줘. 기존 파일 수정은 최소화하고 독립적인 새 파일을 중심으로 구현해 줘.
```

작업을 마치면 `/status`로 메인 에이전트의 작업 맥락 사용량을 본다.

## 2. 서브 에이전트에 같은 일 맡겨 보기 (§11.4)

같은 세션에서 출발선으로 되돌린다.

```text
방금 구현한 자동 완성 변경을 모두 되돌려서 아까 남긴 커밋 상태로 맞춰 줘.
```

`/exit`로 세션을 끝내고 터미널에서 `codex`를 다시 실행한다. `/status`를 본 뒤 요청한다.

```text
서브 에이전트를 활용해 지역명 자동 완성 기능을 구현해 줘. 기존 파일 수정은 최소화하고 독립적인 새 파일을 중심으로 구현해 줘.
```

## 3. 메인에는 요약만 돌려받기 (§11.5)

이번에도 되돌려 달라고 한 뒤 `/exit`로 끝내고 `codex`를 다시 실행한다. 요청에는 역할, 보고 내용,
메인이 하지 않을 일을 함께 적는다.

```text
서브 에이전트를 활용해 지역명 자동 완성 기능을 구현해 줘. 관련 파일 탐색부터 구현·테스트까지 서브 에이전트가 독립적으로 수행하고, 기존 파일 수정은 최소화하며 독립적인 새 파일을 중심으로 구성해 줘. 메인 에이전트에는 수정 파일, 핵심 변경 사항, 테스트 결과, 남은 위험만 간단히 보고하고 불필요한 재검토나 테스트 반복은 하지 마.
```

같은 뜻을 짧게 줄이면 이렇다.

```text
서브 에이전트가 지역명 자동 완성을 구현·테스트해 줘. 새 파일 중심으로 작업하고, 메인은 결과만 요약해.
```

## 4. 메인에 UI 개선을 함께 맡기기 (§11.6)

```text
내비게이션의 이전·다음 버튼에 마우스를 올리면 진행 중 표시가 나타난다. 일반 링크 표시로 바꿔 줘. 조회 후에는 ‘조회가 완료되었습니다’라는 문구가 보이지 않게 해 줘.
```

## 5. 서브 에이전트로 코드 품질 검사하기 (§11.7)

```text
보안·코드 품질·버그 관점별로 독립 서브 에이전트를 하나씩 실행해 코드를 검토해 줘.
```

보고 형식과 메인이 할 일까지 정하면 이렇다.

```text
보안·코드 품질·버그 관점별로 독립 서브 에이전트를 하나씩 실행해 코드를 검토해 줘. 코드는 수정하지 말고, 각 문제의 심각도·파일 위치·영향·수정 방향만 간단히 보고해. 모든 결과가 나오면 중복을 합쳐 우선순위순으로 요약하고, 근거가 부족한 내용은 확인 필요로 구분해 줘. 메인 에이전트는 원본 코드나 전체 로그를 다시 읽지 말고 서브 에이전트 결과만 취합해.
```

요청이 너무 길다면 이렇게 줄인다.

```text
보안·코드 품질·버그 관점별로 독립 서브 에이전트를 하나씩 실행해 코드를 검토해 줘. 메인 에이전트는 서브 에이전트 결과만 취합해.
```

수정까지 맡기려면 “앞의 검토 결과 중 심각도가 높은 항목만 서브 에이전트가 고치고, 바꾼 파일과
이유만 메인에 보고해 줘.”처럼 범위를 좁혀 요청한다.

## 6. /subagents로 확인하고 멈추기 (§11.8)

```text
/subagents
```

실행 중인 서브 에이전트와 이 세션의 에이전트 스레드 목록이 함께 나오고, 하나를 골라 그 작업 창으로
들어갈 수 있다. 더 필요하지 않은 작업은 `/subagents`에서 대상을 고르거나 직접 중지를 요청한다.

```text
security_review 서브 에이전트의 작업을 멈춰 줘.
```

`/ps`는 별도로 실행 중인 셸 프로세스를 확인할 때 쓰고, `/stop`은 그 셸 프로세스를 모두 멈출 때 쓴다.
