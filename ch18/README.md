# 오늘의 국내 시장

국내 주식시장의 일별 시세를 보는 Next.js 대시보드다. 홈(`/`)에는 관심 종목, 주요 지수, 시장 열기, 지수 히트맵과 종목 순위가 있고, `/compare`에서는 두 종목을 나란히 비교한다. 관심 종목·비교 선택·화면 모드는 브라우저에 저장한다. 실시간 매매나 계좌 관리 서비스가 아니다.

## 시작하기: 설치 → 환경변수 → 실행

1. **설치** — Node.js 22 LTS와 npm을 준비하고 저장소 루트에서 실행한다. 잠금 파일을 사용한다.

   ```bash
   npm ci
   ```

2. **환경변수** — `.env.sample`을 로컬 `.env`로 복사하고 발급받은 값을 직접 입력한다. 기존 `.env`가 있다면 덮어쓰지 않는다. 실제 파일·값은 Git, 대화, 로그에 복사하지 않는다.

   ```bash
   cp -n .env.sample .env
   ```

   아래 세 이름이 앱의 키 계약이다. 저장소의 견본과 이 문서에는 값을 비워 둔다.

   ```dotenv
   DATA_GO_KR_SERVICE_KEY=
   NEXT_PUBLIC_SUPABASE_URL=
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
   ```

   | 이름 | 용도와 준비할 권한 |
   |---|---|
   | `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 지수·주식시세 API의 서버 전용 인증 키. 해당 API 활용 신청이 필요하다. `NEXT_PUBLIC_`로 옮기지 않는다. |
   | `NEXT_PUBLIC_SUPABASE_URL` | 시세를 보관하는 Supabase 프로젝트의 공개 API 주소. |
   | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `public.daily_prices`를 읽을 수 있는 공개 키. 테이블 권한과 RLS 정책을 확인한다. service role·secret 키로 대신하지 않는다. |

   Next.js가 로컬 환경 파일을 읽는다. 변경 후 서버를 다시 시작한다. Vercel은 저장소의 로컬 파일을 읽지 않으므로 같은 이름을 대상 프로젝트의 Preview/Production 환경에 별도로 설정하고, 설정 변경을 반영할 배포를 만든다. `NEXT_PUBLIC_` 값은 공개 가능한 정보만 넣으며 빌드 시 반영될 수 있다. MCP 로그인은 앱 환경변수 설정을 대신하지 않는다.

3. **실행** — 개발 서버를 열고 홈과 비교 화면을 확인한다.

   ```bash
   npm run dev
   ```

   기본 주소는 [홈](http://localhost:3000)과 [비교](http://localhost:3000/compare)다. 배포용 실행은 `npm run build` 후 `npm start`다. 키가 없거나 조회가 실패해도 예시 화면은 열릴 수 있으므로, 화면이 열린 것만으로 실제 데이터 연결 성공이라 판단하지 않는다.

## Supabase MCP·Vercel 재연결

MCP는 다음 작업자의 프로젝트 점검 도구다. 앱은 MCP 없이도 환경변수와 HTTP API로 동작한다. 연결 자격증명과 개인 인증 상태는 저장소로 인계하지 않는다.

- **Supabase MCP:** 사용하는 MCP 클라이언트의 연결 설정에서 [공식 연결 안내](https://supabase.com/docs/guides/ai-tools/mcp)에 따라 다시 인증한다. 서버는 `https://mcp.supabase.com/mcp`이며 대상 `project_ref`로 범위를 제한하고 점검에는 `read_only=true`를 사용한다. 프로젝트 이름·참조가 앱의 Supabase 프로젝트와 같은지 확인한 뒤 `public.daily_prices`의 열과 최신 기준일을 읽기 전용으로 확인한다. 다른 프로젝트를 새로 만들거나 스키마를 자동 변경하지 않는다.
- **Vercel MCP:** [공식 연결 안내](https://vercel.com/docs/agent-resources/vercel-mcp)에 따라 `https://mcp.vercel.com` 연결을 인증한다. 실제 제공되는 도구 목록을 확인하고, 올바른 팀·프로젝트·Git 저장소를 선택한다. 최신 Production 배포의 Ready 상태, 전체 커밋 SHA, 프로덕션 주소를 기록한다. 이전 세션의 localhost나 Preview 주소를 프로덕션 주소로 인계하지 않는다.
- **Vercel의 Git 연결:** 프로젝트 설정에서 저장소·루트 디렉터리·Production 브랜치가 이 프로젝트와 `main`을 가리키는지 확인한다. 연결이 끊겼다면 기존 프로젝트에 저장소를 다시 연결한다. MCP 재인증과 Git 연결은 별개다. 실제 배포·환경 설정 변경은 작업 요청 범위를 확인한 뒤 수행한다.

현재 저장소에는 프로덕션 주소나 프로젝트 ID를 확정하는 인계 설정이 없다. 다음 사람이 위 절차로 확인한 주소와 배포 SHA를 함께 기록해야 한다. 마지막 로컬 기능 통합 커밋은 `e0bb7e0`이며, 이것이 프로덕션에 배포되었다는 뜻은 아니다.

## 데이터 출처·이용 조건과 기준일

| 대상 | 출처·필드 |
|---|---|
| 종목 시세·관심 종목·비교·순위 | Supabase `public.daily_prices`의 최신 `trade_date` 전체 행. `stock_code`, `stock_name`, `close_price`, `change_percent`, `trading_value`를 사용한다. |
| 주요 지수·시장 열기·지수 히트맵 | [금융위원회 지수시세정보](https://www.data.go.kr/data/15094807/openapi.do)와 [주식시세정보](https://www.data.go.kr/data/15094808/openapi.do). `GetMarketIndexInfoService/getStockMarketIndex`, `GetStockSecuritiesInfoService/getStockPriceInfo`를 사용한다. |
| 수집 실패 시 화면 | `data/marketSnapshot.js`의 고정 예시. 실제 시세와 구분하는 배지와 안내를 표시한다. |

**이용 조건:** 금융위원회 지수시세정보·주식시세정보는 공공데이터포털 상세 페이지의 이용허락범위가 공공누리 제4유형이고 제3자 제공과 재배포를 금지한다. 그래서 이 대시보드는 내가 보는 용도로만 쓰고, Vercel 배포 주소는 Deployment Protection의 Vercel Authentication을 All Deployments 범위로 켜서 계정에 로그인해야 열리게 잠근다. 저장소와 문서에는 실제 시세 값을 남기지 않고 화면 예시는 `data/marketSnapshot.js`로만 둔다. 주소를 다른 사람과 나누거나 잠금을 풀기 전에 이 조건을 다시 확인한다.

Supabase는 저장소이며 원천 거래소 데이터 자체가 아니다. 외부 수집 작업이 채운 최신 날짜를 앱이 GET으로 읽는다. 이 저장소에는 정기 수집 스케줄러나 데이터 쓰기 경로가 없다. Supabase 조회는 캐시하지 않으며 요청 제한 시간은 15초다. 날짜별 전체 행과 건수를 확인하고 불완전한 목록은 사용하지 않는다.

Supabase 설정 누락·빈 테이블·조회 실패 시 종목은 공공데이터 API로 전환한다. API도 실패하면 전체 예시 데이터를 쓴다. Supabase 종목 조회에 성공해도 시장 요약은 별도로 공공데이터 API를 읽는다. 그 API가 실패하면 시장 요약만 예시가 되며 `시장 요약: 예시 데이터`로 알린다. 종목과 시장 요약의 기준일이 다르면 각각 표시한다. API 캐시는 1시간, 요청별 제한 시간은 15초다.

공공데이터는 실시간이 아니며 공식 안내상 **기준일 다음 영업일 오후 1시 이후** 갱신된다. 주말·공휴일·거래소 휴장일에는 새 거래일 시세가 없을 수 있다. 기준일이 오늘과 다르다는 이유만으로 오류로 판단하지 말고, 최근 거래일과 공식 제공 시각 및 Supabase 수집 완료 여부를 확인한다. 화면의 ‘현재가’는 최신 수집 일별 종가, ‘오늘 등락률’은 표시된 기준일의 전 거래일 대비다. 지수 그래프도 장중 실시간 흐름이 아닌 최근 일별 종가다.

## 계산 기준

- **시장 열기 = (3% 이상 상승한 종목 수 ÷ 전체 수집 종목 수) × 100.** 현재 화면 문구도 ‘3% 이상 상승 종목 비율’이다. 단순 양수 종목 전체의 비율과 다르다. 비율을 그대로 쓰고 가중치·보정·감성 점수 같은 가공 점수는 만들지 않았다. 표시는 소수 첫째 자리, 유효하지 않은 분모는 0, 범위는 0~100%로 제한한다.
- 공공데이터 집계 대상은 KOSPI·KOSDAQ·KONEX 시세 행이며 우선주도 포함한다. 시장 열기는 Supabase의 관심 종목이나 상위 순위만으로 계산하지 않는다.
- 종가 `clpr`는 원, 등락률 `fltRt`는 %를 그대로 쓴다. 거래대금 `trPrc`/`trading_value`만 100,000,000으로 나눠 억원 단위로 포맷한다. 순위는 수집된 전체 종목에서 등락률·거래대금 기준 각 상위 5개다.

## 결정 기록과 이유

1. **조선·게임·2차전지는 TOP 10 테마지수로만 정확히 매핑한다.** 인계 시 합의한 방향은 최신 공식 응답에서 확인한 세 테마지수를 쓰되 산업분류 지수처럼 표현하지 않는 것이다. 기존 보고서에 기록된 명칭은 조선 `KRX 조선 TOP10`, 게임 `KRX 게임 TOP 10`, 2차전지 `KRX 2차전지 TOP 10`이다. 구현 시 최신 응답의 정확한 `idxNm`·`idxCsf`·기준일을 대조하고, ‘테마지수’라는 성격과 TOP 10 범위를 화면에 명시해야 한다. 비슷한 이름·테마 전체를 의미하는 값으로 확대 해석하지 않는다.
2. **화장품은 확인되지 않은 값을 만들지 않는다.** 대응 지수를 확인하지 못했으므로 필수소비재 등 유사 지수나 종목을 임의로 합친 산식으로 채우지 않는다. 공식 매핑이 확인될 때까지 실제 데이터 화면에서는 제외한다.
3. **보유 종목·수익률은 넣지 않는다.** 계좌 연동이 없는 상태에서는 수량·매입가·평가손익을 신뢰할 근거가 없어 가짜 숫자가 된다. 사용자가 고르는 관심 종목은 보유 종목을 뜻하지 않는다.
4. **비교는 두 종목까지만 둔다.** 한 화면에서 현재가와 등락률을 나란히 보는 목적에 맞춘다. 같은 종목이면 다른 종목을 선택하도록 안내하고 기존 유효 선택을 유지한다.
5. **‘예시 데이터’ 안내를 지우지 않는다.** 수집 실패 또는 실제 데이터 부재를 알리는 표시다. 실제 시세로 오해하지 않도록 전체 예시와 시장 요약만 예시인 경우 모두 구분한다.
6. **화면 모드는 시스템 우선으로 시작한다.** 명시 선택 전에는 컴퓨터의 화면 설정과 변경을 따르고, 사용자가 선택한 모드를 저장해 우선한다. 홈과 비교 모두 적용하며 등락은 색과 부호를 함께 사용한다.

**현재 구현:** KRX 업종 8개와 TOP 10 테마 3개를 정확한 `idxNm`·`idxCsf`로 매핑한다. 2026-10-17 공식 API 최신 응답(기준일 2026-10-15)에서 `KRX 조선 TOP10 지수`, `KRX 게임 TOP 10 지수`, `KRX 2차전지 TOP 10 지수`와 `테마지수` 분류를 확인했다. 화면은 ‘업종·테마 히트맵’이며 세 카드에 ‘TOP 10 · 테마지수’를 표시한다. 같은 기준일의 유효한 값만 사용하고 화장품은 공식 대응 지수 미확인으로 실제 데이터에서 제외한다. [DATA_REPORT.md](./DATA_REPORT.md)의 과거 제외 기록과 현재 기준을 구분해 기록했다.

## 검증과 알려진 한계

코드를 바꾸면 검증부터 한다. `npm run lint`와 `npm test`를 실행하고 종료 결과를 보고한다. `npm test`는 Node 테스트와 `next build`를 함께 실행한다. 홈·비교 화면의 라이트/다크, 시스템 설정 반영, 선택 저장, 중복 안내, 기존 관심 종목과 예시 안내를 실제 브라우저에서도 확인한다.

배포한 뒤에는 [verify-market-dashboard Skill](./.agents/skills/verify-market-dashboard/SKILL.md)로 프로덕션 배포 SHA·화면과 실제 조회·런타임 로그·환경변수 이름 계약·Git 비밀 노출을 읽기 전용으로 최종 확인한다. MCP 기능이 부족한 항목은 미확인으로 보고하며 로컬 빌드만으로 배포 성공을 단정하지 않는다.

- 화면은 최소 너비 1200px의 데스크톱 중심이다. 모바일 최적화는 미완료다.
- 선택은 해당 브라우저의 localStorage에만 남는다. 다른 기기 동기화가 없고 저장 차단·초기화 시 사라질 수 있다.
- 최신 날짜가 오래돼도 Supabase 조회 자체는 성공할 수 있다. 신선도 경보와 정기 수집 운영은 별도 과제다.
- 외부 API 지연·호출 한도·불완전한 응답과 서로 다른 출처의 기준일 차이가 있을 수 있다. 예시 데이터의 오래된 날짜는 현재 시세가 아니다.
- 화장품 공식 대응 지수는 미확인이다. 로그인·결제·실제 계좌 연동은 프로젝트 범위 밖이다.

## 복구 방법

- **시세가 예시로만 보일 때:** 안내를 없애지 말고 기준일과 실패 영역을 확인한다. 환경변수 이름·설정 환경, 공공데이터 API 활용 승인, Supabase 테이블의 최신 날짜·전체 행·공개 읽기 권한을 점검한다. 키 값을 출력하지 않는다. 설정을 고쳤으면 로컬 서버를 재시작하거나 필요한 배포를 만들고 실제 조회를 재확인한다.
- **브라우저 선택이 잘못됐을 때:** 개발자 도구의 해당 사이트 저장소에서 필요한 항목만 초기화한다. 키는 `market-dashboard:watchlist`, `market-dashboard:comparison`, `market-dashboard-theme`이다. 테마 저장값을 제거하면 시스템 설정으로 돌아간다. 사이트 전체 저장소를 지우면 다른 선택도 잃는다.
- **코드 회귀:** 먼저 변경 내용을 보존하고 원인을 확인한다. 공유된 `main`을 강제 초기화하지 말고 문제가 된 커밋을 되돌리는 별도 커밋을 만든다. 병합 커밋은 부모 방향을 확인한 뒤 처리한다. 테스트·빌드·화면 검증 후 필요한 배포를 진행한다.
- **배포 회귀:** Vercel의 같은 프로젝트에서 현재 Production 배포와 이전 정상 배포의 ID·SHA·주소를 확인하고, [Instant Rollback](https://vercel.com/docs/instant-rollback) 절차로 정상 배포를 복원한다. 이용 가능 범위·권한·대상은 대시보드에서 확인한다. 롤백은 Git 코드, 외부 데이터와 DB 변경을 되돌리지 않는다. 복구 후 프로덕션 주소·SHA·실제 화면·로그를 재확인하고, Git에도 원인 수정 또는 revert를 남겨 다음 배포가 문제를 되살리지 않게 한다. 검증 Skill은 롤백을 실행하는 도구가 아니다.

## 남은 일

- 화장품은 공식 대응 지수를 확인하기 전까지 실제 데이터에서 제외한다.
- Supabase 시세 수집 담당자·스케줄·실패 알림·거래일별 완전성/신선도 확인 절차를 정한다. 앱의 읽기 경로와 수집 작업을 혼동하지 않는다.
- 인계받은 계정으로 MCP를 재연결하고 실제 Production 프로젝트·주소·배포 SHA를 기록한 뒤 배포 후 검증을 수행한다.
- 모바일 화면과 저장 오류 접근성 안내를 개선한다. 범위 확대 전에 위 결정 기록을 유지할지 확인한다.
