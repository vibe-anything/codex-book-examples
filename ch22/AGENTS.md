# 다음 AI 세션 작업 규칙

이 파일은 이 디렉터리와 하위 파일에 적용한다.

## 시작 전 필수 확인

1. 코드를 열거나 작업을 나누기 전에 `README.md`의 **데이터의 성격**, **계산 기준**, **결정 기록**, **알려진 한계**를 먼저 읽는다.
2. `git status --short --branch`, 현재 브랜치, 현재 worktree 경로를 확인한다. 기존 변경은 소유자가 따로 있다고 가정하고 보존한다.
3. `PROMPTS.md`는 과거 과정의 기록으로만 참고한다. 현재 구현이나 README의 결정 기록과 충돌하면 추측하지 말고 근거를 확인한다.
4. 데이터 원천이나 업종 매핑을 바꾸는 작업이라면 `API_CHECK.md`의 확인일·근거와 `lib/marketData.js`의 `SECTOR_INDEX_MAP`을 함께 확인한다.

## 코드를 바꾸면 검증부터

코드를 변경한 뒤 다음 기능으로 넘어가거나 결과를 공유하기 전에 영향 범위가 작은 검증부터 실행한다. 기본 검증은 아래 두 명령이다.

```bash
node --test lib/*.test.js
npm test
```

- `node --test lib/*.test.js`는 라이브러리 단위 테스트다.
- `npm test`는 `next build`를 실행하는 Production 빌드 검증이며 단위 테스트를 대신하지 않는다.
- 표시·계산 소스 로직을 바꾼 턴에는 반드시 같은 턴에 `npm test`를 실행한다.
- 실패하면 실패 명령과 핵심 원인을 그대로 보고하고, 검증되지 않은 상태를 성공으로 표현하지 않는다.
- 다른 사람에게 공유하기 전과 배포 상태를 최종 인계하기 전에는 `verify-market-dashboard` Skill을 읽기 전용으로 실행한다. 이 Skill은 배포 상태, 배포 화면·API, 런타임 로그, 환경변수 **키 계약**, Git 비밀 값 흔적을 확인한다. 실제 환경변수 값은 읽거나 출력하지 않고, Skill 결과의 `PASS`·`WARNING`·`BLOCKED` 표를 남긴다.

## 데이터·상태 계약

- 업종을 추가하거나 이름을 바꾸기 전에는 현재 공식 지수명과 분류를 다시 확인한다. 이름이 비슷한 지수로 대신하지 않으며, 매핑을 바꾸면 `SECTOR_INDEX_MAP`, `lib/exampleMarketData.js`, 관련 테스트, `API_CHECK.md`, README의 결정 기록을 같은 변경에서 갱신한다.
- 화면의 가격과 등락률은 일별 종가와 해당 거래일 등락률이다. 이를 실시간 가격이나 개인 수익률처럼 표현하지 않는다.
- 관심 종목은 Supabase 프로젝트가 공유하고, 비교할 두 종목과 화면 모드는 각 브라우저에 저장한다. 이 저장 경계를 바꾸면 제품 동작 변경으로 보고 README와 테스트를 함께 갱신한다.

## 화면 모드 규칙

- 저장된 사용자 선택이 없을 때는 컴퓨터의 `prefers-color-scheme` 설정을 따른다.
- 사용자가 밝은/어두운 모드를 고르면 `market-dashboard-theme`에 저장된 선택이 컴퓨터 설정보다 우선한다.
- 컴퓨터 설정이 바뀌어도 저장된 사용자 선택을 덮어쓰지 않는다.
- 이 우선순위를 바꾸거나 저장값을 초기화하는 UI를 추가하려면 제품 동작 변경으로 보고 README와 테스트를 함께 갱신한다.

## 병렬 작업 규칙

- 병렬 작업은 작업별 브랜치와 Git worktree로 분리한다. 여러 세션이 같은 작업 디렉터리에서 파일을 고치지 않는다.
- 각 작업자는 자기 worktree의 경로·브랜치·dirty 상태를 확인하고 자기 범위만 커밋한다.
- 보조 세션은 조사, 구현, 테스트, 자기 브랜치 커밋까지만 한다. merge, rebase를 통한 통합, 원격 push, Vercel 배포는 하지 않는다.
- 메인 세션만 변경을 검토하고, 전체 검증을 실행한 뒤 하나씩 통합한다.
- 충돌하거나 제품 결정이 필요한 변경은 보조 세션이 임의로 해결하지 말고 메인 세션에 근거와 함께 넘긴다.
- 현재 디렉터리가 아직 Git에서 untracked라 worktree를 만들 수 없다면, 메인 세션이 먼저 검토 가능한 기준 커밋을 준비한다. 이를 피해 같은 디렉터리를 공유하지 않는다.

## 하지 말 것

- **없는 데이터를 예시 값으로 채우지 않는다.** 공식 원천에서 동등한 데이터를 검증하지 못한 업종은 화면에서 빼는 것이 현재 결정이다. `exampleMarketData`는 전체 수집 실패를 알리는 명시적 fallback일 뿐, 일부 빈 칸을 그럴듯하게 메우는 재료가 아니다.
- **`예시 데이터` 안내를 지우거나 약화하지 않는다.** 이 안내는 수집 실패 상태를 실제 시세로 오해하지 않게 하는 안전장치다.
- **인증키나 환경변수 값을 코드·문서·테스트 fixture·로그·커밋에 적지 않는다.** `.env.sample`에는 승인된 키 이름과 빈 값만 둔다. 검사 중에도 `.env`나 Vercel의 실제 값을 출력하지 않는다.
- **로그인, 결제, 실제 증권 계좌 연동, 보유 수량·매입가·개인 수익률, 매매 기능을 구현하지 않는다.** 신원·금융·보안 설계가 필요한 별도 제품 범위이며, 현재 데이터만으로 만들면 가짜 숫자나 위험한 기능이 된다.
- **검증 없이 배포하거나 자동 수정하지 않는다.** `verify-market-dashboard`는 상태를 판정하는 Skill이며 자동 수정·실제 배포 권한을 뜻하지 않는다.
