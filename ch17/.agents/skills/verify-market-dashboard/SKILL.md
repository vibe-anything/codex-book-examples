# 주식 대시보드 배포 후 최종 검증

이 저장소 전용 Skill이다. 먼저 [앱별 완료 기준](references/market-dashboard.md)을 읽고 대상 커밋의 `README.md`, `DATA_REPORT.md`, `.env.sample`과 대조한다. 문서와 코드가 충돌하면 임의로 기준을 완화하지 말고 보고한다. 검증 결과는 한국어로 응답하며 별도 요청 없이 보고서 파일을 쓰지 않는다.

## 권한과 판정

- 검증은 읽기 전용이다. 자동 수정, Git 변경, 배포·재배포, 환경변수 값 조회·변경을 금지한다. 실제 `.env` 파일, 로컬 프로세스 환경, Vercel 환경변수 값을 읽지 않는다. 계약에서는 이름만 추출하고 값을 출력하지 않는다.
- Vercel 조회(배포 상태·주소·로그·배포 화면 및 배포 응답)는 이미 연결된 **Vercel MCP만** 사용한다. 제공된 도구의 읽기 전용 기능을 확인하고 사용한다. Vercel CLI, 일반 웹·브라우저 도구, curl, 직접 REST 호출, 다른 도구 설치·로그인으로 보완하지 않는다.
- MCP 미연결, 권한 부족, 화면 열기·실제 조회·로그 기능 부재, 관측 범위 부족은 해당 영역의 WARNING이다. 확인되지 않은 항목을 PASS로 만들지 않는다. 독립적으로 가능한 나머지 검증은 계속한다.
- PASS는 필요한 직접 증거가 모두 확인된 경우, WARNING은 확인 불가·범위 부족·미확정 의심, BLOCKED는 완료 기준 위반이 확인된 경우다. 전체는 하나라도 BLOCKED이면 BLOCKED, 그 외 하나라도 WARNING이면 WARNING, 모두 PASS일 때만 PASS다.
- 비밀값은 도구 출력 전부터 제거한다. 원문 비밀, 인증 쿼리, 환경변수 값, 로그 전체를 출력하지 않는다. 발견 근거는 경로·행·커밋 SHA·비밀 유형 등 비밀을 포함하지 않는 위치 정보로 남긴다.

## 검증 순서

아래 순서를 지킨다. 앞 단계가 미확인이어도 가능한 후속 독립 검사는 수행하고, 같은 배포임을 확인할 수 없는 후속 관측은 PASS 근거로 쓰지 않는다.

1. **배포 상태**: 로컬 Git HEAD의 전체 SHA, 브랜치, 작업 트리 상태 및 로컬 원격 추적 ref의 최신성을 확인한다. 이 저장소에 연결된 Vercel 프로젝트의 최신 **프로덕션** 배포를 MCP로 조회해 배포 ID, 생성 시각, 상태, 전체 커밋 SHA, 프로덕션 주소를 기록한다. 저장소 최신 커밋과 배포 커밋이 같고 Ready여야 PASS다. 최신 성공 배포로 골라 바꾸거나 Preview로 대체하지 않는다. 원격 최신성을 입증할 정보가 없으면 로컬 HEAD만 확인했다고 명시하고 WARNING으로 남긴다. 명확한 커밋 불일치·실패·취소는 BLOCKED, 진행 중·프로젝트 연결 불명·SHA 부재는 WARNING이다. 미커밋 변경은 배포 검증 대상에 포함되지 않음을 밝힌다.
2. **배포 화면·API**: 확인한 프로덕션 주소를 Vercel MCP로 직접 열고 같은 배포를 가리키는지 확인한다. 앱별 기준에 따라 출처·기준일·종가 표시와 실제 시세 조회 성공을 확인한다. HTTP 200이나 로컬 코드·과거 보고서·빌드 성공만으로 PASS를 주지 않는다. MCP가 제공하는 화면·배포 응답·관련 요청 증거로 실제 조회와 예시 여부를 확인한다. 화면 및 실제 조회를 직접 확인하지 못하면 WARNING, 필수 표시 누락·실제 조회 실패·예시 데이터 대체가 확인되면 BLOCKED다. 주소와 확인 시각을 남긴다.
3. **런타임 로그**: 같은 프로덕션 배포의 최근 60분 Runtime Logs를 MCP로 조회하며 2단계 조회 시각도 포함한다. 실제 기간·시간대·필터·페이지 범위·관측 요청 수·5xx 건수를 기록한다. 동일 경로와 오류 유형의 5xx가 2회 이상이면 반복 오류로 BLOCKED, 단발 5xx는 WARNING이다. 전체 기간과 모든 페이지가 확인되고 관측된 요청에서 5xx가 없으면 PASS다. 로그 미수집·접근 불가·잘린 결과·짧은 기간·요청 관측 없음은 WARNING이다. 빈 로그만으로 정상이라고 판정하지 않는다.
4. **환경변수 계약**: 대상 커밋의 앱 실행 코드·설정에서 요구하는 변수 이름을 `.env.sample`과 앱별 기준 문서의 계약과 비교한다. 직접 접근뿐 아니라 별칭, 구조 분해, 헬퍼, 동적 접근을 추적한다. 코드가 요구하지만 계약에 없는 이름은 BLOCKED다. 동적 이름을 확정할 수 없거나 계약 문서가 서로 다르면 WARNING이다. 프레임워크 표준 변수는 코드 맥락과 근거를 명시해 앱 전용 변수와 구분하며, 이름이 비슷하다는 이유로 허용하지 않는다. Vercel 환경변수 값이나 목록을 조회해 보완하지 않는다. 이 검사는 실제 값 설정 여부를 보증하지 않는다.
5. **Git 비밀 검사**: Git 추적 파일과 로컬에서 접근 가능한 모든 refs의 커밋 이력을 검사한다. 삭제·변경된 과거 파일 내용도 포함한다. 이름만 있는 `.env.sample` 계약은 허용하지만 실제 `.env`, `.env.local` 등 환경 파일 추적과 키·토큰·인증정보 커밋은 BLOCKED다. 공개용 키와 비밀 키는 용도를 구분하고 판단 불명확한 후보는 WARNING이다. 기존 도구나 로컬 읽기 전용 처리로 검사하되 새 도구는 설치하지 않는다. 내용 검사는 결과를 출력하기 전에 비밀 원문을 제거하는 방식으로 수행한다. `git log -p`, `git show`, 비밀 검색 결과를 원문 그대로 출력하지 않는다. shallow clone, 누락된 refs, 파일·이력 검사 실패나 부분 검사는 WARNING이다. 전체 검사에서 발견이 없을 때만 접근 가능한 범위에 대해 PASS로 보고하며 원격의 미수집 이력까지 안전하다고 단정하지 않는다. 비밀이 발견되어도 파일 삭제·이력 재작성·키 폐기 등을 직접 실행하지 않는다.

## 고정 보고 형식

매번 전체 판정 한 줄 바로 아래에 다음 다섯 행 표를 둔다. 상태는 PASS, WARNING, BLOCKED만 사용한다. 자리표시자는 실제 근거로 교체한다. 관련 행에 SHA, 배포 ID·주소·확인 시각, 로그 기간, 계약 파일, Git 검사 범위를 포함한다. 미확인 이유와 사람이 수행할 구체적 확인을 다음 행동에 적는다. 확인된 위반은 사람이 해결 후 재검증하도록 안내하며 직접 수정하지 않는다. 수동 확인 제안은 PASS 근거가 아니다.

전체 판정: {PASS 또는 WARNING 또는 BLOCKED}

| 영역 | 상태 | 확인한 근거 | 다음 행동 |
|---|---|---|---|
| 배포 상태 | {상태} | {근거} | {행동 또는 없음} |
| 배포 화면·API | {상태} | {근거} | {행동 또는 없음} |
| 런타임 로그 | {상태} | {근거} | {행동 또는 없음} |
| 환경변수 계약 | {상태} | {근거} | {행동 또는 없음} |
| Git 비밀 검사 | {상태} | {근거} | {행동 또는 없음} |
