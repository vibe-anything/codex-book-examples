# 다음 AI 세션의 작업 규칙

## 작업 시작 전

- 작업 전에 [README의 결정 기록](./README.md#결정-기록과-이유)을 읽는다. 설치·키 계약·데이터 출처·현재 구현과 결정의 차이·남은 일도 확인한다.
- `pwd`, Git 상태·브랜치·HEAD·워크트리 목록을 확인하고 기존 작업을 보존한다. 과거 보고서나 로컬 성공을 현재 배포의 증거로 사용하지 않는다.
- 현재 코드는 KRX 업종 지수 8개와 조선·게임·2차전지 TOP 10 테마지수 3개를 매핑한다. 테마는 정확한 명칭과 `테마지수` 분류를 함께 검사하고 화면에 TOP 10 범위와 테마임을 명시한다. 매핑 변경 시 최신 공식 응답의 정확한 명칭·분류·기준일을 확인하고 README·DATA_REPORT·Skill 참조 기준도 함께 정합화한다. 화장품은 공식 대응 지수 확인 전까지 실제 데이터에서 제외한다. 문서·코드의 차이를 조용히 덮거나 완료로 보고하지 않는다.

## 코드를 바꾸면 검증부터

- 표시·계산 로직을 바꾸면 프로젝트 루트에서 **`npm test`를 실행하고 결과를 보고한다.** 이 명령에는 Node 테스트와 `next build`가 포함된다. 실행 시작만 기록하지 말고 종료와 성공·실패를 확인한다. 검증 이후 코드를 바꾸면 다시 실행한다.
- 코드 변경 시 `npm run lint`도 실행하고, 변경 목적에 맞는 예시 데이터로 검증한다. 홈·비교 양모드와 기존 관심 종목 등 관련 동작을 브라우저에서 확인한다. 실제 키나 외부 서비스에 쓰는 테스트를 만들지 않는다.
- 문서만 바꿨다면 링크·환경변수 이름·구현과의 정합성을 검사하고 검사 범위를 보고한다. 코드 검사나 배포 검증을 했다고 주장하지 않는다.
- 배포 후 최종 검증에는 [verify-market-dashboard Skill](./.agents/skills/verify-market-dashboard/SKILL.md)을 읽고 적용한다. 이 Skill은 이 저장소의 Vercel 프로덕션을 **읽기 전용**으로 검증하며, 일반 개발·수정·배포·롤백용이 아니다.
- Skill의 배포 상태·화면과 실제 조회·로그·환경변수 계약·Git 비밀 검사를 따른다. 배포 관련 증거는 연결된 Vercel MCP의 제공 기능만 사용한다. 관측 불가는 WARNING으로, 확인된 위반은 BLOCKED로 보고한다. 권한·보호 훅을 우회하거나 로컬 빌드로 배포 PASS를 대신하지 않는다.

## 화면 모드와 표시

- 처음에는 컴퓨터 화면 설정을 따르고 시스템 설정 변경도 반영한다. 사용자가 고른 화면 모드는 브라우저에 저장해 시스템 설정보다 우선한다. ‘시스템 설정’을 다시 고르면 시스템을 따른다.
- 홈·비교의 모든 카드·표·입력·링크를 라이트/다크에서 읽을 수 있게 한다. 상승·하락은 색뿐 아니라 `+`·`−` 부호로도 구분한다. 저장소 접근 실패가 화면 전체를 깨뜨리지 않게 한다.
- 시장 열기는 전체 수집 종목 중 **3% 이상 상승한 종목의 비율**을 그대로 쓴다. 임의 가공 점수를 만들거나 양수 종목 비율로 의미를 바꾸지 않는다.
- ‘예시 데이터’ 및 시장 요약 예시 안내, 출처·기준일·종가 안내를 유지한다. 수집 실패를 감추거나 실시간 시세로 표현하지 않는다.

## 병렬 작업

- 병렬 작업의 작업 파일은 기능별 **별도 Git 워크트리·브랜치**로 나눈다. 같은 폴더를 여러 에이전트가 동시에 수정하지 않는다. 결과 통합은 **메인 Codex**가 수행한다.
- 시작점과 수정 범위를 정하고 각 에이전트에게 경로·브랜치를 전달한다. 각 에이전트는 실제 작업장·브랜치·HEAD를 확인한 뒤 작업한다. 겹치는 파일의 소유자를 미리 정한다.
- 워크트리나 검사 준비에 권한이 필요하면 승인을 요청한다. 별도 작업장에 쓸 수 없으면 같은 폴더로 우회하지 말고 멈춰 알린다. 생성한 경로와 실제 실행 구간을 기록한다.
- 각 에이전트는 본인 범위만 예시 데이터로 검사하고 필요한 `npm test`를 완료한 뒤 해당 파일만 커밋한다. 메인은 시작점 대비 변경을 검토하고 통과한 결과를 하나씩 통합한다. 충돌이나 제품 결정이 필요하면 현재 병합을 중단하고 알린다.
- 통합 뒤 자동 검사·빌드·관련 화면과 기존 기능을 확인한다. 정리는 작업장에 남은 변경과 main 포함 여부를 확인한 뒤 허가된 대상만 처리한다. push·배포·워크트리 정리는 요청 범위를 따른다.

## 하지 말 것과 이유

- **공식 매핑을 검증하지 못한 업종을 유사 지수나 임의 산식으로 채우지 않는다.** 다른 대상의 수치를 같은 의미인 것처럼 보이게 한다. 화장품은 대응 지수 확인 전 제외하고, 세 TOP 10 테마지수도 산업분류 지수로 표현하지 않는다.
- **인증 키를 코드에 적지 않는다.** 유출과 클라이언트 노출을 막기 위해 환경변수로 주입하고 `.env.sample`에는 이름과 빈 값만 둔다. 실제 환경 파일·값·인증 URL을 읽어 출력하거나 커밋·대화·로그에 복사하지 않는다. 공공데이터 비밀 키를 `NEXT_PUBLIC_`로 만들지 않고 Supabase service role 키로 공개 키를 대체하지 않는다.
- **로그인·결제·실제 계좌 연동은 이 프로젝트 범위 밖이다.** 시장 정보를 읽는 대시보드이며 해당 기능에는 별도 인증·보안·제품 설계가 필요하다. 계좌 근거 없는 보유 수량·수익률도 만들지 않는다.
- **테스트·배포·최신 데이터 확인을 추정해서 완료로 보고하지 않는다.** 관측한 커밋·화면·기준일과 실행 결과, 미확인 범위를 구분한다.
