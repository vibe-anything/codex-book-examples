# Project Instructions

## 시작 전에

- 작업 전에 `README.md`의 **결정 기록**, **알려진 한계**, **남은 일**을 읽는다.
- 현재 Git 상태와 기존 미커밋 변경을 확인하고, 다른 사람의 변경을 덮어쓰지 않는다.
- 데이터 출처·기준일·폴백 계약을 바꾸는 제안은 README의 기존 결정과 충돌하는지 먼저
  확인한다.

## 코드를 바꾸면 검증부터

- 코드 변경 후 완료 보고나 커밋보다 검증을 먼저 한다. 관련 단위 테스트를 실행하고
  결과를 보고한다.
- 표시·계산 로직을 바꾸면 반드시 `npm test`를 실행한다. 이 명령의 Node 테스트와
  Next.js 프로덕션 빌드가 모두 성공해야 한다.
- 배포 후 점검이나 프로덕션 최종 검수에는 `$verify-market-dashboard` Skill을
  사용한다. 이 Skill은 읽기 전용 검증용이며 기능 구현, 자동 수정, 실제 배포,
  환경변수 값 조회에 사용하지 않는다.
- 테스트 실패, 빌드 실패, Skill의 WARNING·BLOCKED를 숨기지 말고 원인과 미검증 범위를
  함께 보고한다.

## 화면 모드 규칙

- 저장된 사용자 선택이 없으면 처음에는 컴퓨터의 `prefers-color-scheme` 설정을 따른다.
- 사용자가 라이트 또는 다크 모드를 고르면 브라우저에 기억하고 이후에는 컴퓨터
  설정보다 그 선택을 우선한다.
- 새 화면과 컴포넌트도 두 모드에서 상승·하락·보합을 색과 부호로 함께 구분하고,
  텍스트 대비를 유지한다.

## 병렬 작업 규칙

- 병렬 작업이 필요하면 기능별 작업 파일과 브랜치를 별도 Git 워크트리로 나눈다.
- 각 작업자는 시작 전에 자신의 작업 경로·브랜치·수정 범위를 확인하고 맡은 파일만
  수정한다.
- 각 워크트리에서 관련 테스트를 통과시키고 변경을 검토 가능한 단위로 남긴다.
- 결과 검토, 충돌 해결, 순차 병합, 최종 통합 검증은 메인 Codex가 담당한다.
  서브에이전트가 메인 작업장에 직접 병합하거나 서로의 범위를 임의로 수정하지 않는다.

## 하지 말 것

- 공식 지수명과 분류를 검증하지 못한 업종을 유사 지수나 임의 산식으로 채우지 않는다.
  지수 구성과 가중치가 다른 값을 업종 수익률처럼 보이게 만들 수 있기 때문이다.
- 조선·게임·2차전지의 공식 `TOP 10` 테마지수를 일반 산업분류 지수처럼 표현하지
  않는다. 사용한다면 공식 이름과 `테마지수` 분류를 정확히 매핑하고 테마임을 표시한다.
- 대응 지수를 확인하지 못한 화장품을 소비재 지수나 임의 종목 평균으로 대신하지 않는다.
- 인증키와 환경변수 값을 코드, 문서, 테스트 fixture, 로그, 커밋에 적지 않는다. 코드에는
  런타임 환경변수 참조만 두고 견본 파일의 값은 비워 둔다.
- `예시 데이터` 배지와 실패 안내를 삭제하거나 실제 데이터처럼 꾸미지 않는다. 이는
  외부 수집 실패와 데이터 출처를 사용자에게 알리는 안전장치다.
- 로그인·결제·실제 증권 계좌 연동을 구현하지 않는다. 계좌 인증, 금융 거래, 개인 보유
  정보는 이 학습용 읽기 전용 대시보드의 범위 밖이다.
- 계좌 연동 없이 보유 수량·평균 매수가·수익률을 임의 숫자로 만들지 않는다.
