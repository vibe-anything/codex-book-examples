# 9장 요청문 — 긴 세션을 정리하며 기능을 확장하기

이 폴더는 9장을 **끝낸 직후** 상태다. `ch08`을 복사한 뒤 아래 순서로 만들었다. 실제 API를 부르므로
`.env`에 자기 인증 키가 있어야 한다.

## 1. 목록 개선을 한 번에 맡기지 않는다 (§9.1)

책은 다음 요청을 실수하기 쉬운 예로 든다. 보내지 않는다.

```text
목록 화면을 사용하기 좋게 전부 개선해 줘. 페이지 이동, 계약월 선택, 면적 필터, 빈 상태, 오류 상태도 다 넣어 줘.
```

대신 기능을 하나씩 붙이고 바로 확인한다.

```text
목록 화면에서 페이지와 행 수를 입력받는 폼을 제거하고, 하단에 이전·다음 버튼으로 페이지를 넘기는 형태로 바꿔 줘. 한 페이지에 10개씩 보여 줘. 페이지 요청 파라미터와 전체 건수는 아래 API 문서를 참고해 줘.
https://www.data.go.kr/data/15126469/openapi.do
```

## 2. 계약년월을 달력 위젯으로 바꾸기 (§9.2)

```text
계약년월 입력 상자는 텍스트인데, 쉽게 입력할 수 있는 기본 달력 위젯으로 구현해 줘.
```

## 3. 전용 면적 필터와 빈 상태 붙이기 (§9.3)

```text
다음 작업을 구현해 줘.
- 전용 면적 필터 추가
- 계약월 ‘연, 월’로 표시
- 데이터가 없을 때 화면 추가
- API 오류 시 화면 추가
```

## 4. Context window가 차기 전에 끊는다 (§9.4)

```text
/status
```

Context window의 남은 비율을 본다. 숫자보다 잔량이 줄어드는 흐름을 본다.

```text
/compact
```

`/compact`는 뒤에 문장을 붙여도 받지 않는다. 남길 내용(이번 작업에서 결정한 요구사항, 바뀐 파일,
확인 방법, 남은 작업)은 실행하기 전에 짧게 정리해 두고, 요약한 뒤에 다시 확인한다.

## 5. /new로 새 대화 시작하기 (§9.5)

```text
/new
```

Git 저장소인 폴더에서는 새 대화를 어디서 이어 갈지 묻는 창(Where should the new conversation run?)이
먼저 뜬다. 지금 폴더에서 이어 가려면 1번 Use current Git worktree를 고른다.

## 6. 상세 화면을 2단으로 고치기 (§9.6)

새 대화이므로 첫 요청에 필요한 맥락을 다시 담는다.

```text
목록 화면 개선은 끝났고, 상세 화면에서 key-value 형식이 1단으로 나오는데, 2단으로 바꿔 줘.
```

```text
key에서 영어를 제거해 줘.
```

## 7. codex resume으로 다시 들어오기 (§9.7)

Codex를 종료했다가 다시 열 때는 터미널에서 실행한다. 현재 작업 폴더의 최근 세션을 바로 연다.

```bash
codex resume --last
```

다른 작업 폴더의 세션까지 보려면 이렇게 한다.

```bash
codex resume --all
```

```text
지난 세션을 이어서 작업할 거야. 먼저 현재 파일 상태를 읽고, 지난 세션 요약과 어긋나는 점이 있는지 확인해 줘. 아직 수정하지 말고, 이어서 할 작업 후보만 말해 줘.
```

## 8. /fork로 다른 안 시험하기 (§9.8)

지금 대화에서 `/fork`를 실행한 뒤 새 대화에 요청한다.

```text
/fork
```

```text
기존 2단 key-value grid는 유지하되, 상단에 거래 금액, 전용 면적, 계약일을 요약 카드로 보여 주는 안을 제안해 줘. 기존 파일을 수정하기 전에 필요한 변경을 먼저 설명해 줘.
```

원래 대화로 돌아가려면 `/resume`으로 세션 목록을 열어 갈라 나오기 전 대화를 고른다. 두 안을 모두
실제로 구현해 비교할 때는 깃 워크트리를 함께 쓰는 방법도 있다. 9장에서는 실행하지 않고, 17장에서
다룬다.

```bash
git worktree add ../real-estate-summary-card -b feature/summary-card
```

## 9. 자동 기억에는 취향만 남기기 (§9.9)

자동 기억을 쓰려면 `~/.codex/config.toml`에 다음 설정을 더한다. 프로젝트 폴더가 아니라 내 컴퓨터의
Codex 설정이다.

```toml
[features]
memories = true
```

설정을 켠 뒤 Codex 대화창에서 `/memories`를 실행해 기존 자동 기억을 사용할지, 이번 대화를 나중에
자동 기억으로 만들지 고른다. 규칙을 직접 적어 저장하는 명령은 아니다.

```text
/memories
```
