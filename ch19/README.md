# 한국 시장 대시보드 인수인계

이 폴더는 국내 주식의 최신 일별 종가를 보여주는 Next.js 대시보드다. 데이터 출처와
기준일을 화면에 함께 표시하고, 관심 종목·두 종목 비교·화면 모드 선택은 브라우저의
`localStorage`에 저장한다. 실시간 시세, 계좌, 주문 기능은 제공하지 않는다.

## 처음 실행하는 3단계

1. 의존성을 설치한다.

   ```bash
   npm ci
   ```

2. 환경변수 파일을 만들고 세 값을 로컬에서만 채운다.

   ```bash
   cp .env.sample .env
   ```

   `.env`는 Git에 포함하지 않는다. 키 이름과 용도는 아래 **환경변수 계약**을 따른다.

3. 개발 서버를 실행하고 `http://localhost:3000`을 연다.

   ```bash
   npm run dev
   ```

코드를 공유하거나 배포하기 전에는 `npm test`를 실행한다. 이 명령은 Node 테스트와
Next.js 프로덕션 빌드를 차례로 수행한다.

## 환경변수 계약

`.env.sample`에는 아래 이름만 두며 값은 항상 비워 둔다.

```dotenv
DATA_GO_KR_SERVICE_KEY=
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
```

| 이름 | 용도 |
| --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 금융위원회 지수·주식 시세 API 인증키 |
| `NEXT_PUBLIC_SUPABASE_URL` | `daily_stock_prices`가 있는 Supabase 프로젝트 API URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 해당 테이블을 `SELECT`할 수 있는 Supabase publishable key |

이 세 이름은 `.env.sample`, Vercel 환경변수, `lib/dataGoKr.js`,
`lib/supabaseMarketData.js`에서 정확히 같아야 한다. publishable key도 코드나 문서에
직접 적지 않고 환경변수로만 전달한다. 앱은 Supabase에 쓰지 않으며 `daily_stock_prices`의
읽기 정책만 필요하다.

## 다음 사람의 MCP 재연결

MCP 연결은 개발·검증 도구의 연결이며 앱 런타임 환경변수를 대신하지 않는다. 이 저장소는
`.vercel` 프로젝트 메타데이터를 추적하지 않으므로 새 컴퓨터나 새 AI 세션에서 기존
프로젝트를 다시 식별해야 한다. 프로젝트 이름만 보고 새 프로젝트를 만들거나 임의로
연결하지 않는다.

### Supabase MCP

Supabase 공식 MCP 설정 화면에서 기존 프로젝트의 `project_ref`를 확인한 뒤 프로젝트
범위와 읽기 전용 모드를 사용한다. `<PROJECT_REF>`는 실제 값으로 바꾸되 명령 결과나
문서에 남기지 않는다.

```bash
codex mcp add supabase --url "https://mcp.supabase.com/mcp?project_ref=<PROJECT_REF>&read_only=true&features=database,docs,debugging"
codex mcp login supabase
```

OAuth에서 이 프로젝트가 속한 조직만 승인한다. 연결 후 테이블 목록에서
`daily_stock_prices`가 보이는지, 읽기 전용 조회가 되는지만 확인한다. 운영 데이터에 쓰기
권한을 주지 않는다. 가능하면 개발·로컬 프로젝트를 연결하고, 실제 운영 데이터가 있는
프로젝트를 확인해야 할 때는 프로젝트 범위와 `read_only=true`를 유지한다. 로컬 Supabase
스택을 확인할 때는 `http://localhost:54321/mcp`를 별도 연결로 사용한다. 자세한 보안
옵션은 [Supabase MCP 공식 문서](https://supabase.com/docs/guides/ai-tools/mcp)를 따른다.

### Vercel MCP

Vercel 공식 OAuth MCP를 연결한다.

```bash
codex mcp add vercel --url https://mcp.vercel.com
codex mcp login vercel
```

연결 후 Vercel MCP의 Git 저장소 메타데이터, 프로덕션 도메인, 배포 커밋 SHA를 함께
대조해 기존 프로젝트를 찾는다. 후보가 둘 이상이면 추측하지 않는다. 팀·프로젝트 slug를
확정한 뒤에는 `https://mcp.vercel.com/<teamSlug>/<projectSlug>` 형태의 프로젝트 범위
엔드포인트를 사용할 수 있다. [Vercel MCP 공식 문서](https://vercel.com/docs/agent-resources/vercel-mcp)에도 같은 OAuth 엔드포인트와 Codex 연결법이 정리되어 있다.

Supabase·Vercel MCP가 없는 상태에서 `verify-market-dashboard` Skill을 실행하면 Skill은
설치나 로그인을 대신하지 않고 해당 영역을 `WARNING`으로 남긴다. 재연결은 사람이 명시적으로
수행하고, Skill은 연결된 도구를 읽기 전용으로 검증하는 역할만 맡는다.

## 데이터 출처와 기준일

화면은 아래 순서로 데이터를 읽는다.

1. **Supabase**: `daily_stock_prices`에서 가장 최신 `price_date`의 모든 종목을 페이지 단위로
   읽는다. 현재 테이블에는 종목 시세만 있으므로 이 출처일 때 지수 카드와 업종 히트맵은
   표시하지 않는다.
2. **공공데이터**: Supabase 조회가 실패하면 금융위원회 `주식시장지수시세정보`와
   `주식시세정보`의 최신 `basDt`를 읽는다. KOSPI·KOSDAQ 종목만 사용한다.
3. **예시 데이터**: 두 실제 출처가 모두 실패하면 화면 구조를 유지할 수 있는 샘플을
   표시한다. 이 값은 실제 투자 정보가 아니다.

공공데이터의 일별 시세는 거래일 당일 실시간 값이 아니며 다음 영업일 오후에 갱신되는
것을 기준으로 한다. 주말·공휴일·임시 휴장일에는 새 거래일 데이터가 생기지 않으므로
마지막 영업일의 기준일이 계속 보이는 것이 정상이다. 화면의 기준일은 컴퓨터의 오늘 날짜가
아니라 응답의 `price_date` 또는 `basDt`다. 지수와 종목의 최신일이 다르면
`지수 YYYY.MM.DD · 종목 YYYY.MM.DD 기준`처럼 둘을 따로 표시한다.

각 원격 조회는 한 시간 동안 재검증될 수 있다. Supabase 적재가 멈춰도 앱은 그 테이블의
가장 최신 행을 정상 데이터로 읽으므로, 운영에서는 기준일이 최근 영업일인지 별도로 감시해야
한다.

## 계산 기준

시장 열기는 현재 데이터에 포함된 전체 종목 중 **등락률이 3% 이상인 상승 종목의 비율**을
그대로 백분율로 표시한다.

```text
시장 열기(%) = 3% 이상 상승 종목 수 / 전체 유효 종목 수 × 100
```

분모가 없거나 값이 잘못되면 0으로 처리하고 결과 범위만 0~100으로 제한한다. 가중치,
보정치, 분위수, 심리 지표를 섞은 별도 점수는 만들지 않는다. 상승률·하락률·거래대금 순위는
각 원본 값을 정렬한 상위 5개다.

## 결정 기록

아래 결정은 화면의 의미를 지키기 위한 것이므로 근거 없이 되돌리지 않는다.

- 최신 공식 응답에서 `KRX 조선 TOP10 지수`, `KRX 게임 TOP 10 지수`,
  `KRX 2차전지 TOP 10 지수`는 **테마지수**로 확인했다. 이름은 정확히 식별하되 이를
  산업분류 업종 지수인 것처럼 히트맵에 매핑하지 않는다. 현재 업종 히트맵에는 정확히
  대응하는 KRX 업종 지수가 확인된 항목만 나온다.
- 화장품은 정확히 대응하는 공식 업종 지수를 확인하지 못했다. 비슷해 보이는 지수나 임의
  종목 묶음·가중 산식으로 빈칸을 채우면 공식 지수처럼 오해하게 되므로 표시하지 않는다.
- 계좌 연동이 없는데 보유 수량·평가금액·수익률을 넣으면 모두 가짜 숫자가 된다. 따라서
  관심 종목은 코드만 로컬에 저장하고 보유 종목·수익률 영역은 만들지 않았다.
- 종목 비교의 목적은 서로 다른 종목을 한 화면에서 나란히 읽는 것이다. 비교 대상을 두
  종목으로 제한해 정보 밀도와 선택 규칙을 단순하게 유지했다.
- `예시 데이터` 배지는 수집 실패를 사용자에게 알리는 안전장치다. 화면이 그럴듯해 보이게
  하려고 숨기거나 실제 출처명으로 바꾸면 안 된다. 프로덕션 공유 전 검증에서는 이 배지가
  보이면 실패로 판정한다.
- 화면 모드는 저장된 선택이 없을 때 컴퓨터 설정을 따르고, 사용자가 고른 시스템·라이트·
  다크 모드를 저장해 우선한다. 상승·하락은 어느 테마에서도 색과 `+`/`−` 부호로 함께
  구분한다.

## 알려진 한계

- 모든 값은 일별 종가다. 실시간·장중 시세가 아니다.
- 이 저장소에는 Supabase로 시세를 적재하는 스케줄러가 없다. 앱은 이미 적재된 행만 읽는다.
- Supabase 최신일이 오래되어도 자동으로 공공데이터로 전환하지 않는다. 데이터 신선도 경고와
  적재 모니터링이 아직 없다.
- Supabase 출처에서는 현재 스키마 한계로 시장 지수와 업종 히트맵이 없다.
- 관심 종목, 비교 종목, 화면 모드는 브라우저별 `localStorage`에만 남으며 계정 간 동기화되지
  않는다.
- 공공데이터 응답이 비거나 일부 페이지만 수집되거나 8초 안에 끝나지 않으면 예시 데이터로
  내려간다.
- 로그인, 결제, 주문, 실제 증권 계좌 연동은 프로젝트 범위 밖이다.

## 장애 복구와 배포 롤백

### 로컬·데이터 복구

1. `git status --short`로 사용자 변경을 먼저 보존하고 `npm ci`, `npm test`로 재현한다.
2. 화면의 출처 배지와 기준일을 확인한다. `예시 데이터`라면 안내 문구의 Supabase 오류와
   공공데이터 오류를 숨기지 말고 원인부터 해결한다.
3. Supabase는 환경변수 **이름**, 프로젝트 URL 대응, `daily_stock_prices`의 최신
   `price_date`, `SELECT` 정책을 확인한다. 키 값은 로그나 이슈에 붙이지 않는다.
4. 공공데이터는 인증키 설정, 응답 코드, 최신 `basDt`, 전체 페이지 수집 여부를 확인한다.
5. 수정 후 `npm test`를 다시 통과시키고, 배포를 공유하기 전
   `verify-market-dashboard` Skill로 대상 커밋과 최신 프로덕션 배포를 검증한다.

### Vercel 프로덕션 롤백

1. 장애가 난 현재 배포의 커밋 SHA와 직전 정상 프로덕션 배포를 확인한다.
2. Vercel 프로젝트의 Production Deployment에서 **Instant Rollback**으로 마지막 정상 배포를
   선택한다. 이 동작은 기존 빌드로 도메인을 되돌리므로 새 빌드를 만들지 않으며, 당시 빌드의
   환경변수와 외부 Supabase·API의 현재 상태가 서로 다를 수 있음을 확인한다.
3. 롤백 뒤 화면의 출처·기준일·종가·등락률과 최근 5xx를 다시 확인한다. 롤백 상태에서는 새
   push의 프로덕션 도메인 자동 할당이 꺼질 수 있으므로, 수정 배포를 올릴 때 **Undo Rollback**
   또는 정상 배포 승격으로 자동 할당을 복구한다.
4. 코드 이력도 되돌려야 하면 공유 브랜치에서 `git reset --hard`로 기록을 지우지 말고
   `git revert <문제-커밋-SHA>`로 되돌림 커밋을 만든다. Preview와 `npm test`를 확인한 뒤
   정상 배포를 승격한다.
5. 마지막으로 `verify-market-dashboard` Skill을 다시 실행해 배포 SHA 일치, 실제 화면,
   최근 5xx, 환경변수 이름 계약, Git 비밀 검사를 모두 확인한다.

Vercel 요금제에 따라 선택 가능한 과거 배포 범위가 다르고, Instant Rollback은 환경변수를
다시 빌드하지 않는다. 세부 동작은 [Vercel Instant Rollback 공식 문서](https://vercel.com/docs/instant-rollback)를 따른다.

## 남은 일

- 다음 영업일 시세를 `daily_stock_prices`에 적재하는 스케줄러와 실패 알림을 저장소 안에
  재현 가능한 형태로 추가한다.
- 최신 기준일이 기대한 영업일보다 오래되면 경고하거나 공공데이터로 전환하는 신선도 정책을
  합의하고 테스트한다.
- 조선·게임·2차전지·화장품에 정확한 공식 업종 지수가 새로 제공되는지 정기적으로 확인하되,
  확인 전에는 현재의 미표시 결정을 유지한다.
- 관심 종목·종목 비교·화면 모드의 브라우저 상호작용 E2E 테스트를 추가한다.
- Vercel 프로젝트 식별 정보와 운영 담당자를 비밀이 아닌 별도 운영 문서에 기록하고 5xx·
  데이터 적재 지연 알림을 구성한다.
