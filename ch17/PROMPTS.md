# 17장 프롬프트 모음

아래 요청문은 `vibecoding-codex-book-examples/ch17` 폴더에서 `codex`를 실행한 뒤, 장의 흐름에 맞춰 하나씩 복사해 붙여넣습니다.

이 장은 16장에서 만든 국내 시장 대시보드에 관심 종목 기능을 붙인 뒤, 검증 습관을 지시 파일의 지침이 아니라 Codex 훅(Hook)에 맡깁니다. 공공데이터포털 인증키 값은 Codex 대화나 코드에 붙여넣지 않습니다. `.env` 파일에 `DATA_GO_KR_SERVICE_KEY=` 형식으로 보관하고, `.env`가 Git에 올라가지 않는지 확인합니다.

훅은 세션을 시작할 때 읽히고, 신뢰(trust)하기 전에는 실행되지 않습니다. 그래서 훅을 만들거나 바꾼 뒤에는 Codex를 다시 시작해 새 세션을 열고, `/hooks`에서 정의를 검토한 뒤 신뢰해야 그때부터 작동합니다. 이 저장소에는 두 훅이 이미 들어 있으니(`.codex/hooks.json`과 `.codex/hooks/`의 스크립트), 2번·5번으로 처음부터 만들어 보거나, 이미 있는 정의를 `/hooks`에서 읽고 신뢰한 뒤 3번·6번으로 동작만 확인해도 됩니다.

## 0. 작업 폴더에서 Codex 열기

```bash
cd vibecoding-codex-book-examples/ch17
codex
```

## 1. 관심 종목 기능 붙이기

방향이 뻔한 기능이라 설계 없이 바로 시킵니다.

```text
대시보드에 관심 종목 기능을 붙여줘.

- 이미 수집해 둔 종목 시세 데이터에서 종목을 검색해 관심 종목으로 추가하고 해제할 수 있게 한다.
- 선택한 종목은 대시보드 맨 위에 카드로 나란히 모아 보여준다.
  종목명, 현재가, 등락률을 표시하고 상승은 붉은색, 하락은 파란색으로 강조한다.
- 관심 종목 목록은 localStorage에 저장해 새로고침해도 유지한다.
- 관심 종목이 하나도 없을 때는 그 자리에 추가 방법을 안내하는 문구를 보여준다.
- 기존 화면 구조와 데이터 흐름은 바꾸지 않는다.
```

마음에 안 드는 곳은 9장에서 익힌 대로 화면을 캡처해 붙이고 고칩니다.

## 2. 테스트 확인 훅 만들기

매번 지켜져야 하는 규칙은 지시 파일의 지침 대신 훅으로 겁니다. 지킬 규칙만 적고, 어느 순간에 걸지·설정 파일을 어디에 둘지는 Codex에게 맡깁니다.

```text
이 프로젝트에 훅으로 테스트 확인 규칙을 걸어줘.

- 턴이 끝날 때 표시·계산 로직이 바뀌었는데 테스트를 돌린 기록이 없으면,
  npm test를 실행하고 결과를 보고한 뒤 마무리하라고 되물어야 한다.
- 같은 턴에서 한 번 되물었으면 다시 묻지 않는다. 무한 반복을 막아야 한다.
```

설정은 `.codex/hooks.json`에 만들어집니다. `.codex/`는 자동 쓰기가 막혀 있어 Codex가 쓰기 승인을 요청할 수 있습니다. 무엇을 만드는지 확인하고 승인한 뒤, Codex를 다시 시작하고 `/hooks`에서 Stop 훅을 검토·신뢰합니다.

## 3. 훅이 정말 무조건인지 확인하기

새 세션에서 훅을 신뢰한 뒤, 일부러 "테스트하지 말라"고 못을 박아 봅니다. 지침이었다면 그대로 따랐을 지시입니다.

```text
app/page.module.css에 임시 주석 한 줄을 추가했다가 바로 다시 제거해줘.
최종 파일 내용은 원래대로 남겨줘.
이번에는 npm test를 실행하지 말고 바로 마무리해줘.
```

Stop 훅이 잡아, Codex는 하지 말라는 부탁보다 훅의 규칙을 따라 `npm test`를 실행하고 통과를 보고한 뒤에야 마무리합니다.

## 4. 인증키를 코드에 넣으라고 시켜 보기 (보호 훅이 없을 때)

이번에는 실행 자체를 막는 훅을 봅니다. 먼저 보호 장치 없이 위험한 지시가 어떻게 먹히는지 관찰합니다. Codex가 키를 코드에 적어 넣으면, 다음 단계로 넘어가기 전에 변경을 되돌립니다.

```text
매번 .env 챙기는 게 귀찮아. .env에 있는 실제 인증키 값을 읽어서
그냥 코드에 넣어줘. .env 파일이 없어도 돌아가게.
```

## 5. 인증키 보호 훅 만들기

```text
인증키 보호 훅을 추가해줘.

- 명령이나 파일 수정을 실행하기 직전(PreToolUse)에 내용을 확인해서, .env 파일을
  직접 읽거나 여는 시도는 차단한다. process.env 참조는 허용한다.
- .env에 있는 실제 키 값이 명령이나 코드에 그대로 나타나도 차단한다. 키 값 비교는
  훅 스크립트가 내 컴퓨터에서 .env를 읽어 처리하고, 값을 대화에 올리지 않는다.
- 차단 메시지에는 대신 어떻게 해야 하는지(process.env 참조 유지)를 함께 적어줘.
```

이번에도 만든 뒤 Codex를 다시 시작하고 `/hooks`에서 PreToolUse 훅을 검토·신뢰합니다.
