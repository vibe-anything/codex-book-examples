# 15장 요청문 — 주식 대시보드를 클라우드에 배포하고 검증하기

이 폴더는 15장을 **끝낸 직후** 상태다. 15장은 코드를 바꾸지 않으므로 파일은 `ch14`와 같다.
GitHub 빈 저장소 만들기, Vercel 가입과 연결, 배포 주소 잠그기, 환경 변수 입력은 **사람 몫**이다.

3부의 시세는 이용 조건(공공누리 제4유형, 제3자 제공·재배포 금지)상 다른 사람에게 보여 줄 수
없다. 그래서 배포 주소는 내 Vercel 계정으로 로그인해야 열리게 잠근다(§15.5).

## 1. 올리기 전 비밀 값 점검 (§15.2)

먼저 사람이 직접 확인한다.

```text
공개 전 점검:
□ .env가 Git의 추적 파일이나 커밋 기록에 들어 있지 않다.
□ 코드와 배포 설정 어디에도 인증 키 값이 직접 적혀 있지 않다.
□ 화면에 예시 데이터가 진짜인 척 남아 있지 않다(기준일 표시 확인).
□ 무엇이 바뀌었고 어떻게 되돌리는지 설명할 수 있다.
```

앞의 둘은 Codex에게 확인시킨다.

```text
공개 전 점검을 부탁해.
- .env가 Git의 추적 파일이나 커밋 기록에 들어 있지 않은지 확인해 줘.
- 코드와 설정 파일에 인증 키 값이 직접 적힌 곳이 없는지 찾아 줘.
- .env 파일 자체는 열지 말고, 문제를 찾으면 고치기 전에 먼저 알려 줘.
```

## 2. GitHub에 올리기 (§15.3)

github.com에서 `stock-dashboard` 같은 이름으로 **빈 저장소**를 만든다(README 추가 같은 초기화
옵션은 모두 끈다). 그다음 푸시를 맡긴다.

```text
이 프로젝트를 GitHub 저장소 https://github.com/<내 계정>/stock-dashboard.git 에 올려 줘. 원격 연결부터 푸시까지 끝나면 무엇을 했는지 알려 줘.
```

이 실행에서는 Codex가 원격 `origin`을 등록하고 `main`을 푸시했다. 처음 푸시할 때 GitHub
인증을 요구하면 로그인은 사람이 한다. 푸시가 끝나면 저장소 페이지에서 파일이 올라왔는지 본다.

## 3. Vercel에 연결하고 첫 배포 (§15.4)

vercel.com에서 Continue with GitHub로 가입하고, New Project에서 대시보드 저장소를 [Import]한다.
Next.js로 인식되고 요금제는 Hobby다. 이번 실습은 누락 증상을 보려고 환경 변수를 비운 채
Deploy를 누른다. 빌드가 끝나면 `프로젝트이름.vercel.app` 형태의 프로덕션 주소가 나온다.

## 4. 배포 주소 잠그기 (§15.5)

실제 시세를 연결하기 전에 주소부터 잠근다.

1. Vercel 프로젝트의 Settings에서 Deployment Protection을 연다.
2. 맨 위 Vercel Authentication의 Require Log In은 처음부터 켜져 있다. 옆의 범위가 Standard
   Protection이면 대표 주소는 잠기지 않으므로, 범위를 All Deployments(Protect all domains)로
   바꾸고 [Save]를 누른다. Hobby 요금제에서도 고를 수 있다.
3. 시크릿 창으로 배포 주소를 연다. 대시보드 대신 Vercel 로그인 화면이 나와야 한다. Vercel에
   로그인해 둔 내 브라우저에서는 그대로 열린다.

## 5. 첫 배포에서 드러난 문제 (§15.6)

주소를 열면 화면은 보이지만 ‘예시 데이터’ 배지와 함께 실제 수집에 실패했다는 안내가 붙어 있다.
배포 환경에 환경 변수가 없기 때문이다.

## 6. Vercel MCP로 배포 로그 읽기 (§15.7)

```bash
codex mcp add vercel --url https://mcp.vercel.com
```

브라우저 승인 창에서 어느 팀에 붙일지 고르고, 접근할 프로젝트도 `stock-dashboard` 하나로
좁힌다(Access to all current and future projects를 끔). 그다음 [Authorize]를 누른다. 승인한 뒤
도구 목록은 이렇게 본다.

```text
/mcp verbose
```

```text
방금 Vercel에 배포한 대시보드가 예시 데이터로 돌아. 배포 상태랑 최근 로그를 확인해서 내가 Vercel에서 무엇을 설정해야 하는지 알려 줘.
```

이 실행에서 Codex는 배포가 READY인 것과 최근 24시간 런타임 오류가 0건인 것을 확인했다. 코드가
실패를 예시 데이터로 받아 내기 때문에 오류 로그가 남지 않는다. 대신 프로젝트에 등록된 환경
변수가 0개라는 것을 찾아, `DATA_GO_KR_SERVICE_KEY`·`NEXT_PUBLIC_SUPABASE_URL`·
`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`가 모두 빠졌다고 짚었다.

## 7. 환경 변수를 넣고 재배포하기 (§15.8)

Vercel 프로젝트의 Settings → Environment Variables에 **사람이 직접** 세 값을 넣는다. Vercel
MCP에도 환경 변수를 만드는 도구가 있지만, 값을 Codex에게 건네면 키가 대화 기록에 남는다.
이름은 `.env.sample`이 알려 준다.

| 이름 | 유형(Type) |
| --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | Secret(저장한 뒤 값을 다시 볼 수 없다) |
| `NEXT_PUBLIC_SUPABASE_URL` | Config |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Config |

환경 변수는 넣는 것만으로는 이미 돌고 있는 배포에 적용되지 않는다. Vercel이 띄우는 재배포
버튼으로 다시 배포한 뒤 확인을 맡긴다.

```text
재배포가 끝났으면 배포 주소를 직접 열어서 확인해 줘.
- 화면 안내에서 ‘예시 데이터’ 문구가 사라졌는지
- 실제 시세의 출처와 기준일이 보이는지
- 최근 로그에 같은 오류가 다시 생기지 않았는지
```

이 실행에서 Codex는 새 배포가 READY인 것을 보고, Vercel MCP의 도구로 배포 주소를 직접
가져왔다. 잠근 주소인데도 열리는 것은 이 도구가 내 계정 권한으로 잠깐 쓰는 우회 링크를 만들어
들어가기 때문이다. 보고는 ‘예시 데이터’ 문구 없음, 기준일 `2026.10.15 종가 기준`, 종목은
Supabase `daily_prices`와 지수·시장 열기·업종은 공공데이터포털이 출처, 최근 24시간 오류 0건이었다.

보고만 믿지 않고 주소를 직접 열어 기준일과 실제 시세를 본다. 휴대폰처럼 다른 기기에서는
Vercel에 로그인해 열었을 때 관심 종목이 비어 있어야 한다. 개인 설정은 기기 사이에서 동기화되지
않고 시세만 같은 값으로 보이는 것이 이 설계의 정상이다.
