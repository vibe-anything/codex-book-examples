# 17장 프롬프트 모음

아래 요청문은 13~16장에서 이어 온 주식 대시보드 프로젝트의 루트에서 Codex를 연 뒤, 장의 흐름에 맞춰 하나씩 복사해 붙여넣습니다. 이 장은 배포가 끝난 프로젝트가 전제라서, Vercel 배포와 Vercel MCP 연결(16장)이 살아 있는 자신의 저장소에서 실행해야 합니다.

이 폴더(`ch17`)는 완성된 `verify-market-dashboard` Skill(`.codex/skills/`)까지 들어 있는 스냅숏입니다. 생성 단계(1번)를 그대로 실습하려면 자신의 프로젝트에서 시작하거나, 이 폴더를 복사해 쓰는 경우 `.codex/skills/verify-market-dashboard/`를 지우고 시작합니다. 완성본과 비교만 하려면 이 폴더의 파일을 그대로 읽으면 됩니다.

공공데이터포털과 Supabase의 실제 키 값은 Codex 대화나 이 파일에 붙여넣지 않습니다. 이 장의 검증 Skill도 값이 아니라 이름의 계약만 봅니다.

## 1. `$skill-creator`로 프로젝트 Skill 만들기

```text
$skill-creator

이 프로젝트를 공유하기 전에 배포 상태를 최종 검증하는 Skill을 만들어줘.
이름은 verify-market-dashboard이야. 프로젝트 전용 skill로 만들어줘.
SKILL.md와 보고서는 한국어로 작성해줘.

다음 순서로 읽기 전용 검증을 수행해야 해.
1. Vercel 최신 프로덕션 배포가 Ready이고, 공유하려는 커밋과 같은지
2. 배포된 주소를 직접 열어 데이터 출처·기준일 표시와 /api/watchlist의 200 응답
3. 최근 런타임 로그에 반복되는 5xx 오류가 없는지
4. 코드가 참조하는 환경변수 이름이 저장소의 계약(.env.sample과 앱별 기준 문서)과
   일치하는지 (값 조회 금지, 계약에 없는 이름을 코드가 요구하면 실패)
5. Git 추적 파일과 커밋 이력에 .env나 비밀값이 없는지

Vercel 조회(배포 상태·주소·로그·배포 화면)는 이미 연결된 Vercel MCP만 사용해.
다른 도구를 설치하거나 로그인해서 보완하지 말고, 확인하지 못한 항목은 PASS로
만들지 말고 WARNING으로 남기면서 사람이 할 확인을 안내해줘.

판정은 PASS, WARNING, BLOCKED 세 가지야. 보고는 매번 같은 형식으로 해줘.
전체 판정 한 줄 아래 다섯 행 표(영역 | 상태 | 확인한 근거 | 다음 행동)를 두고,
행 이름은 배포 상태, 배포 화면·API, 런타임 로그, 환경변수 계약, Git 비밀 검사로 고정해줘.
자동 수정, 배포·재배포, 환경변수 값 조회·변경은 금지해줘.
앱별 완료 기준은 references 파일로 분리해줘.
```

저장 위치는 적지 않습니다. 프로젝트 전용으로 만들어 달라고 하면 `.codex/skills/`에 저장되고, 위치는 생성 보고에서 확인합니다.

## 2. 생성된 `SKILL.md` 검토하기

`/mention`을 입력해 `.codex/skills/verify-market-dashboard/SKILL.md`를 선택한 뒤 보냅니다.

```text
이 SKILL.md를 검토해줘.
- 언제 사용하고 언제 사용하지 않는지가 description에 분명한지
- 배포 상태·배포 화면·로그·환경변수·Git 비밀 검사 다섯 가지가 순서대로 있는지
- 보고서의 다섯 행 표 형식과 행 이름이 파일에 고정돼 있는지
- 비밀값 조회나 자동 수정 같은 위험한 동작이 없는지
- 확인하지 못한 항목을 PASS로 처리하지 않는지
문제가 있으면 파일을 고치지 말고 위치와 이유만 알려줘.
```

검토를 마쳤으면 Skill 파일을 커밋하고 푸시합니다. 미커밋 상태로 두면 첫 검증이 "공유 대상 커밋을 확정할 수 없다"며 멈춥니다.

## 3. 최종 검증하기 (첫 호출 — 전체 PASS)

```text
$verify-market-dashboard
현재 주식 대시보드를 다른 사람에게 공유해도 되는지 최종 검증해줘.
파일과 외부 설정은 바꾸지 말고 결과만 보고해줘.
```

환경변수 계약 칸은 Vercel 등록 화면 대신 저장소의 계약(`.env.sample`·기준 문서)과 코드를 대조합니다. Vercel MCP에는 환경변수 이름을 보여 주는 도구가 없기 때문입니다. 등록 화면 확인은 사람 몫으로 남습니다.

## 4. 안전한 실패를 심어 다시 검증하기

서버 코드(예: `lib/supabaseServer.js`)에 다음 한 줄을 추가하고 **커밋까지** 합니다(푸시는 하지 않습니다).

```js
const supabaseAnnoKeyPreview = process.env.SUPABASE_ANNO_KEY;
```

그다음 3번과 같은 검증을 다시 요청합니다. 배포 상태(배포와 다른 커밋)와 환경변수 계약(계약에 없는 `SUPABASE_ANNO_KEY` 요구 — 오타 진단) 두 곳이 `BLOCKED`인지, 값은 어디에도 나오지 않는지 확인합니다.

## 5. 복원하고 마지막으로 확인하기

`git revert`로 실험 커밋을 되돌리고 푸시해 배포와 정렬합니다.

```text
$verify-market-dashboard
방금 실험 커밋을 되돌렸어. 같은 기준으로 다시 검증하고,
아직 BLOCKED나 확인하지 못한 WARNING이 있으면 분리해서 알려줘.
```
