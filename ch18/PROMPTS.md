# 18장 요청문 — 워크트리와 서브에이전트로 두 기능을 동시에 만들기

이 폴더는 18장을 **끝낸 직후** 상태다. `ch17`(검증 Skill까지 끝낸 상태)을 복사한 뒤
아래 요청 하나로 두 기능을 병렬로 만들고 병합했다.

## 1. 두 기능 병렬 요청 (§18.2)

```text
대시보드에 두 기능을 동시에 만들어줘.

만들 것
- 종목 비교: 서로 다른 두 종목의 현재가와 오늘 등락률을 나란히 보여주고, 선택을 기억한다.
  같은 종목을 고르면 다른 종목을 고르도록 알려준다.
- 다크 모드: 처음에는 컴퓨터 화면 설정을 따르고, 내가 고른 화면 모드를 기억한다.
  모든 카드와 상승·하락 정보는 두 화면에서 또렷하게 보여주고, 색과 부호로 함께 구분한다.

진행
- 먼저 지금 작업을 잃을 위험이 없는지 확인해줘.
- 안전하면 기능마다 별도 워크트리와 서브에이전트 한 명을 배정해 병렬로 구현해줘.
- 워크트리는 프로젝트 폴더 안에 만들고, 어디에 만들었는지 경로를 알려줘.
- 각 서브에이전트에게 작업 경로·브랜치·수정 범위를 알려주고, 올바른 작업장인지 확인한 뒤 시작하게 해줘.
- 작업장을 만들거나 검사를 준비하는 데 권한이 필요하면 포기하지 말고 승인을 요청해줘.
- 별도 작업장에 쓸 권한이 없으면 같은 폴더에서 진행하지 말고 멈춰서 알려줘.

완료
- 각 서브에이전트가 맡은 범위만 예시 데이터로 검사해 커밋하게 해줘.
- 둘 다 통과하면 시작점 대비 각 변경을 검토하고 하나씩 합쳐줘. 충돌이나 제품 결정이 필요하면 현재 병합을 중단하고 알려줘.
- 홈과 비교 화면의 두 모드, 기존 기능, 자동 검사와 빌드까지 확인해줘.
- 두 서브에이전트의 실행 구간이 실제로 몇 초 겹쳤는지, 시작 커밋과 최종 결과 사이의 Diff 요약, 최종 주소를 보여줘.
- push·배포·작업장 정리는 하지 마.
```

이 실행의 결과:

- 워크트리 두 곳 `.worktrees/stock-comparison`·`.worktrees/dark-mode`(프로젝트 폴더 안).
- 각 작업장 테스트 22개 통과 → 순차 병합 → **최종 통합 테스트 27개 전부 통과**.
- 커밋 계보: `250f427`(시작) → `0ac53e3`·`f3d651a`(각 기능) → `acf6bc0`·`5b0d51f`(병합).
- 이번 실행에서는 충돌이 나지 않아 §18.2의 충돌 해소 요청문은 쓰지 않았다.

## 2. 작업장 정리 (§18.3)

확인이 끝나면:

```text
최종 결과를 확인했어. 합친 커밋이 원래 프로젝트에 남아 있는지 다시 확인하고, 이번 작업에 만든 워크트리와 작업용 브랜치만 안전하게 정리해줘.
```

## 참고 — 워크트리에는 `.env`가 따라가지 않는다

각 작업장의 검사가 예시 데이터로 도는 이유다(§18.2 주의). 실데이터 화면을 보려면
원래 프로젝트 폴더에서 개발 서버를 띄운다.
