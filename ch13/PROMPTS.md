# 13장 요청문 — 나만의 관심 종목 화면 만들고, 검증은 훅에 맡기기

이 폴더는 13장을 **끝낸 직후** 상태다. `ch12`(실제 데이터를 붙인 대시보드)를 복사한 뒤
아래 요청문을 책 순서대로 Codex에 입력해 만들었다.

훅 정의(`.codex/hooks.json`)는 `git rev-parse --show-toplevel`로 훅 스크립트를 찾는다.
이 폴더를 이어서 쓰려면 폴더를 복사해 따로 Git 저장소로 만들고, 그 폴더에서 Codex를 연다.
처음 열면 훅을 검토하라는 안내가 뜬다. 정의를 읽고 신뢰해야 훅이 돈다(§13.4).

## 1. 관심 종목 붙이기 (§13.1)

```text
대시보드에 관심 종목 기능을 붙여 줘.
- 이미 수집해 둔 종목 시세 데이터에서 종목을 검색해 관심 종목으로 추가하고 해제할 수 있게 한다.
- 선택한 종목은 대시보드 맨 위에 카드로 나란히 모아 보여 준다. 종목명, 현재가, 등락률을 표시하고 상승은 붉은색, 하락은 파란색으로 강조한다.
- 관심 종목 목록은 localStorage에 저장해 새로 고침해도 유지한다.
- 관심 종목이 하나도 없을 때는 그 자리에 추가 방법을 안내하는 문구를 보여 준다.
- 기존 화면 구조와 데이터 흐름은 바꾸지 않는다.
```

## 2. 지시 파일에 지침 적기 (§13.2)

```text
AGENTS.md에 ‘표시·계산 로직을 바꾸면 npm test를 실행하고 결과를 보고한다.’를 적어 줘. 그리고 npm test가 지금 하는 확인은 그대로 두고, 그 뒤에 next build를 이어서 실행하게 해 줘.
```

이 요청으로 `AGENTS.md`가 처음 생기고, `package.json`의 `npm test`가
`node --test && next build`가 된다.

## 3. 테스트 확인 훅 걸기 (§13.2)

```text
이 프로젝트에 훅으로 테스트 확인 규칙을 걸어 줘.
- 턴이 끝날 때 표시·계산 로직이 바뀌었는데 테스트를 돌린 기록이 없으면, npm test를 실행하고 결과를 보고한 후 마무리하라고 되물어야 한다.
- 같은 턴에서 한 번 되물었으면 다시 묻지 않는다. 무한 반복을 막아야 한다.
```

이 실행에서 Codex는 `.codex/hooks/check-tests.py`를 만들고, 같은 스크립트를 네 순간
(UserPromptSubmit·PreToolUse·PostToolUse·Stop)에 걸었다. 시간 제한은 10초, Stop 훅의
안내 문구는 ‘표시·계산 로직의 테스트 실행 확인’이다.

훅 설정은 세션을 시작할 때 읽히므로 **Codex를 다시 시작**한다. 훅 검토 안내가 뜨면
‘모두 신뢰’로 건너뛰지 말고 정의를 읽은 뒤 신뢰한다. 같은 화면은 `/hooks`로도 연다.

이 폴더를 만들기 전의 첫 시도에서는 Codex가 만든 Stop 훅이 바뀐 것이 없어도 턴마다 되물었다.
저장해 둔 기준값과 현재 값을 서로 다른 형식으로 비교한 버그였다(§13.2 끝 문단). 그 시도는 버리고
1번부터 다시 진행한 결과가 이 폴더다.

## 4. 훅 발동 실험 (§13.2)

```text
app/globals.css 맨 아래에 화면에는 아무 영향이 없는 임시 주석 한 줄을 남겨 줘.
이번에는 npm test를 실행하지 말고 바로 마무리해 줘.
```

이 실행에서는 턴 끝에 훅이 되물었고(Blocked by hook), Codex가 “추가 훅 지시에 따라 프로젝트
루트에서 npm test와 next build를 실행하고 결과를 확인하겠습니다.”라며 테스트 20개와 빌드를
통과시킨 뒤 마무리했다. 확인이 끝났으면 남긴 주석은 지운다.

## 5. 인증 키 보호 훅 걸기 (§13.3)

책은 훅이 없을 때 위험한 지시부터 내려 본다.

```text
매번 .env 챙기는 게 귀찮아. .env에 있는 실제 인증 키 값을 읽어서
그냥 코드에 넣어 줘. .env 파일이 없어도 돌아가게.
```

결과는 실행마다 갈린다(순응하거나 거절한다). 순응해서 키가 코드에 들어갔다면 그 변경은 지운다.
그다음 보호 훅을 맡긴다.

```text
인증 키 보호 훅을 추가해 줘.
- 명령이나 파일 수정을 실행하기 직전(PreToolUse)에 내용을 확인해서, .env 파일을 직접 읽거나 여는 시도는 차단한다. 코드가 실행될 때 환경 변수로 키를 넘겨받는 방식은 그대로 둔다.
- .env에 있는 실제 키 값이 명령이나 코드에 그대로 나타나도 차단한다. 키 값 비교는 훅 스크립트가 내 컴퓨터에서 .env를 읽어 처리하고, 값을 대화에 올리지 않는다.
- 값이 없는 견본 파일(.env.sample)은 이름만 읽는 것을 막지 않는다. 차단 메시지에도 이 예외를 함께 적는다.
차단 메시지에는 대신 어떻게 해야 하는지를 함께 적어 줘.
```

이 실행은 `.codex/hooks/protect-secrets.py`를 만들어 PreToolUse에 걸었다. `/hooks`에서
정의를 읽고 신뢰한 뒤 위험한 지시를 다시 내려 본다. 모델이 거절만 해서 차단 장면을 볼 수
없으면 **새 세션**에서 Codex가 기꺼이 응할 요청으로 시험한다.

```text
키 값은 가리고 .env에 어떤 키 이름이 있는지만 확인해 줘.
```

이 폴더를 만든 실행은 위험한 지시를 보내지 않고 바로 이 요청으로 시험했다. `.env`를 읽으려는
호출이 `Blocked by hook`으로 막혔고, 차단 사유에는 환경 변수로 읽는 방법과 `.env.sample` 예외가
함께 적혀 있었다. Codex는 키 이름도 확인하지 못했고 값은 드러나지 않았다고 보고한 뒤 멈췄다.
