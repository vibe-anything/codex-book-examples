# 인증 키 보호 및 테스트 확인 훅

PreToolUse의 protect-secrets.py는 모든 도구 입력(명령, 파일 경로, 패치, 중첩 인자)을 검사한다.
명령의 파일 피연산자·리다이렉션, 파일 도구의 경로, 패치 대상이 `.env` 및 `.env.*`이면 차단한다.
정확히 `.env.sample`인 견본 이름은 허용한다. 문서 heredoc·패치 본문, 커밋 메시지,
검색 패턴·glob에서 이름만 언급하는 것은 허용한다. 실행되는 heredoc과 명령 치환은 별도로 검사한다.
실행 시 환경 변수를 참조하는 코드와 일반 앱 실행은 허용한다.
프로젝트 루트의 `.env*` 파일(견본 제외)에서 비어 있지 않은 할당 값을 로컬 프로세스에서만 읽어
도구 입력과 비교한다. 따옴표, export, 주석을 처리하며 실제 값은 출력·로그·캐시에 남기지 않는다.
견본 파일에도 실제 값을 넣으면 차단한다. 읽기·검사 오류는 값이나 예외 내용을 출력하지 않고 차단한다.
차단 이유에는 환경 변수 주입 방식과 견본 예외를 안내한다.
이 훅은 입력의 평문 검사이며 임의 코드의 난독화, 동적으로 조립한 경로, 간접 실행까지 분석하는
샌드박스는 아니다. 키를 포함한 환경 변수 전체를 출력하는 명령은 사용하지 않는다.

프로젝트의 .codex/hooks.json은 턴 시작 및 도구 실행 전 파일 상태를 기록하고,
Stop에서 표시·계산 관련 파일 변경 후 npm test 완료 기록이 있는지 확인한다.
실행 기록이 없으면 Codex에 테스트 실행과 결과 보고를 요청한다. 사용자에게 실행 허가를 묻는 훅이 아니다.

- 감지 범위: app/, components/, lib/, data/ 전체 파일의 내용, 추가, 삭제.
  의미를 해석하는 대신 이 경로의 변경을 보수적으로 모두 표시·계산 변경으로 취급한다.
- 시작할 때 이미 있던 미커밋 변경은 해당 턴의 변경으로 취급하지 않는다.
- 테스트 기록: PreToolUse에서 npm test 또는 npm run test 명령을 확인하고,
  완료된 PostToolUse 출력에서 현재 test 스크립트의 npm 실행 배너를 확인한다.
  테스트 실행 전후 파일 상태가 같아야 한다. 테스트 후 추가 수정은 다시 검증 대상이다.
  실패도 실행 기록으로 인정하므로 실패 결과 역시 반드시 보고해야 한다.
- 반복 방지: 세션·턴별 reminded 기록과 stop_hook_active를 함께 검사한다.
  같은 턴에서 이미 요청했다면 다시 요청하지 않는다.
- 상태는 OS 임시 폴더에 세션·턴별로 분리해 저장하며 파일 잠금으로 동시 접근을 처리한다.
  대화 본문이나 환경 변수는 저장하지 않는다.
- Python 3와 Codex의 turn_id, 도구 전후 훅 지원이 필요하다.
  다른 실행 래퍼나 출력 잘림 때문에 배너를 확인하지 못하면 보수적으로 한 번 요청할 수 있다.

Codex를 프로젝트에서 다시 열고 /hooks에서 이 프로젝트 훅 정의를 검토하고 신뢰해야 실행된다.
프로젝트의 .codex/ 설정 계층도 신뢰되어야 한다. 훅의 검토·신뢰 상태는 자동으로 변경하지 않는다.

인증 키 훅 회귀 검증은 `node --test test/secrets-hook.test.js`로 실행한다.
훅에 예시 입력을 넣고 키 값 공급 함수를 가짜 값으로 교체하므로 실제 환경 파일을 열지 않는다.
과거 차단된 Skill 작성 명령은 `test/fixtures/blocked-skill-command.txt`를 실행하지 않고 입력으로만 검사한다.
검증은 npm test에도 포함된다. 임시 프로젝트에서 미실행, 실행 완료, 추가 수정,
문서 변경, 파일 삭제, 턴 초기화, 반복 방지를 확인한 뒤 기존 테스트 및 Next.js 빌드를 실행한다.
