# 6장 요청문 — Codex CLI 기본 내장 명령어 사용하기

이 폴더는 6장을 **끝낸 직후** 상태다. `ch05`를 복사한 뒤 6.4에서 `AGENTS.md`에 한 줄을 더했다.
나머지 파일은 `ch05`와 같다.

## 1. /status로 상태를 먼저 확인하기 (§6.1)

```text
/status
```

작업 맥락을 아직 쓰기 전에는 Context window 줄이 보이지 않는다. 대화를 진행한 뒤 다시 보면 나온다.

## 2. /model로 작업에 맞는 모델 고르기 (§6.2)

```text
/model
```

모델을 고르면 추론 수준을 고르는 화면이 이어진다. 기본값은 Low다. 수준을 고른 뒤 [Enter]를
누르면 다음 실행에도 쓰는 기본값으로 저장되고, [S]를 누르면 이번 세션에만 적용된다. 바꾼 뒤에는
선택이 반영됐는지 다시 본다.

```text
/status
```

## 3. /side로 곁가지 질문 빼 두기 (§6.3)

본 작업 대화를 조금 진행한 뒤 `/status`로 Context window 사용량을 보고, 곁가지 질문은 `/side`로
분리한다. 책의 그림을 찍은 실행은 본 작업으로 이렇게 물었다.

```text
실거래가 API 요청 파라미터 LAWD_CD, DEAL_YMD, pageNo, numOfRows가 코드 어디에서 쓰이는지 짧게 정리해 줘.
```

```text
/side 법정동 코드와 행정동 코드는 뭐가 달라?
```

[Ctrl]+[/]로 본 작업 대화와 사이드 대화를 오가고, [Ctrl]+[C]로 사이드 대화를 닫는다. 본 작업
대화로 돌아와 `/status`를 다시 보면 Context window가 앞과 같다.

## 4. 답변 말투와 길이 맞추기 (§6.4)

원하는 방식은 5장에서 만든 `AGENTS.md`에 한 줄로 적어 둔다. 이 폴더의 `AGENTS.md`에는 첫 문단
바로 아래에 이 줄이 있다.

```text
- 답은 결론부터 짧게 쓰고, 필요할 때만 자세히 설명한다.
```

금액과 날짜 표기, XML 응답 처리 기준처럼 이미 적어 둔 규칙과 함께 세션마다 적용된다. 한 번만
다르게 받고 싶다면 요청문에 “짧게 답해 줘.”처럼 덧붙인다.

7장의 첫 `/diff`는 마지막 커밋을 기준으로 바뀐 것을 보여 준다. 이 한 줄을 커밋하지 않았다면
7장의 `/diff`에 `AGENTS.md`의 변경이 나타난다. 책처럼 ‘No changes detected.’에서 출발하려면
7장에 들어가기 전에 이 변경을 커밋해 둔다.
